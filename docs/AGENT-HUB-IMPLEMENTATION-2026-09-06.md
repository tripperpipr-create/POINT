# Agent Hub: состояние внедрения 6 сентября 2026

Проект личный. Утверждённый в диалоге план остаётся действующим: конкретный контракт нужно выполнить, проверить и закончить; широкую цель — подробно обсудить, утвердить и вести в согласованных границах. Размер сообщения и отдельные слова не выбирают режим.

**Поставка Hub operable/accept от 7 сентября выполнена** (live 2×10 + ship в portable/installed). Ниже актуальное состояние исходников. Полный «идеальный» план автономии (единая панель исполнения, Master-watch, confirmed-git/сеть, глубже merge UX) ещё не закрыт. Политика: [AGENT-HUB-ORCHESTRATOR-NETWORK-POLICY.md](AGENT-HUB-ORCHESTRATOR-NETWORK-POLICY.md).

## Что реализовано и проверено

| Область | Реальное состояние |
| --- | --- |
| H01: выбор агентов | В контексте Мастера есть стабильные ID, роли, инструменты и сведения о готовности. Проверяется содержимое отправляемого запроса. |
| H02: достоверность проверок | Результаты различаются по инструменту, аргументам, cwd и ревизии. Последующий провал/timeout того же контроля отменяет успех; другая команда его не закрывает. Диагностический провал не превращается автоматически в обязательный зелёный тест. |
| Постановка | Сохраняются mode, исходный запрос, версии, решения, неизвестные, границы, критерии, права и бюджет. До двух вопросов за реплику; очевидные дефолты стека не интервьюируются. Полная точная задача не требует интервью. |
| Утверждение | Проект запускается только с утверждением текущей версии; изменение существенных условий аннулирует старое утверждение. Модель не может присвоить утверждение. Для precise сохраняется подтверждение исполнения. |
| Исполнитель precise | Один этап исполнителя без модельного расширения плана. Полный контракт попадает в промпт. Готовый результат с ручным критерием получает needs_review; это не автоматически проверенный успех. |
| Права задания | Профиль и снимок исполнения сужаются до разрешений задания до preflight. Сохраняются ASK/DENY. Источник кода/отчёт не получают право править файлы. Запрет команд охватывает пользовательские инструменты независимо от их ID. |
| Изоляция проекта | Автоматическое исполнение project требует сильной Docker-границы; Cursor runtime для структурированного задания отклоняется. Применение Change Set остаётся отдельным решением. |
| Токены и деньги | Атомарные резервации учитывают корневой квест, дочерние лимиты и параллельные запросы. Planner и learning резервируют с QuestID. Обсуждение до Quest остаётся на лимите workspace и показывается отдельной строкой; coverage помечен как partial. Один ledger на planner-вызов (outcome `orchestrator_plan`). |
| Пауза / контроллер | ActiveSeconds считает только model+tools; ожидание approval/pause исключено. Checkpoint сохраняется; Resume/ContinueFromCheckpoint и одноразовое ExtendActiveTime доступны. После перезапуска resumable paused переживает MarkInterrupted; невозобновляемые interrupted. |
| Завершение | Отдельные машинные, ручные критерии и ожидаемый исход воспроизведения. Потеря итогового события не считается успехом. Ошибка записи доказательства останавливает Run. При нескольких изменяющих исполнителях общий результат не считается проверенным без проверки слияния. |
| Журнал действия | Перед действием сохраняются запрос и начало с callId. Если запись результата или применённой правки не удалась, Run останавливается с unknown_outcome; автоматический retry запрещён. |
| Защита запуска | Один сохранённый этап нельзя запустить дважды или подменить его исполнителя/поручение. Повтор всего прерванного структурированного исполнения запрещён до реализации восстановления из проверенной точки. |
| Границы CRUD | Создание/перенос дочернего Quest через старый API не позволяет получить или снять утверждённые полномочия, изменить цель или бюджет. |
| Интерфейс | Режим, версия, редактирование задания, критерии, права и утверждение. Ответы продолжают ту же карточку, в том числе после ошибки модели; привязка сохраняется в состоянии панели. Есть явное новое обсуждение. |
| Обучение | Evidence pack с исходами tools (без тел файлов). Уроки из успехов и провалов (`failed_or_regressed_run` → recovery). Apply всегда `applied_unproven`; `applied_proven` только при canary `effect=improved` или позже real historical benchmark compare (`CompareAgentBenchmarks`). Shadow не фейкает proof через skill_outcomes. Exact skill revision: Skill skip, Memory/Instruction всё ещё учатся. Двухпроходный рецензент + `workflowDigest`. Индекс принципов по квестам агента; portable Memory по-прежнему 2 workspace. Куратор пишет merge-предложения в журнал без silent apply. |

SQLite: добавочные миграции 38 (brief_json / история версий) и 39 (run_checkpoints). Старые задания без brief сохраняют прежний путь исполнения и не становятся автономными автоматически.

## Реальные модельные проверки

Локальная Ollama qwen3.5:9b. Это проверки постановки на фиксированных публичных запросах, без запуска задач, платных API и изменения пользовательского проекта. Модель исполнялась локально на CPU; измерения нельзя переносить на другие модели и устройства.

| Запрос | Итог | Время | Входные / выходные токены |
| --- | --- | --- | --- |
| Полностью описанный Go Clamp, только код, без файлов и команд | precise / ready, без вопросов, права не расширены | 73,56 с | 1450 / 240 |
| Приложение для личного использования без требований | project / discussion, вопросы, без утверждения и исполнения | 77,35 с | 1364 / 237 |

Последний набор прошёл 2/2, по одному модельному раунду. Это **не** требуемые два прохода десяти задач и не оценка качества реального автономного приложения.

До успешного прохода сохранены неудачи: timeout, отсутствие brief, неверный вид критериев и ошибочная классификация широкой задачи как chat. Исправлены передача окна контекста Ollama, порядок intent перед brief в JSON-схеме, противоречивый пример manual-критерия, избыточное повторение требований и общий таймаут локального обсуждения. Обсуждение ограничено 190 секундами целиком, один HTTP-запрос Ollama — 180 секундами; остальные провайдеры сохраняют 90/100 секунд. Контекст выбранного задания не обрезается молча: переполнение возвращает ошибку с сохранением карточки.

Локальные журналы: `.tmp/real-task-intake-9b-intent-first.log` (PASS), предыдущие `.tmp/real-task-intake-9b-*.log` (включая FAIL). Подробные ответы модели выводятся только в opt-in тесте на фиксированных данных.
