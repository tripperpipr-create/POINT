# Зависимости

Последняя проверка: 26 августа 2026 года. Это отчёт о доступных обновлениях, а не
разрешение автоматически поднимать версии.

## Политика

1. Сначала выполнить read-only аудит.
2. Обновлять по одному связанному стеку: БД, Wails, Go `x/*`, frontend или
   runtime расширения.
3. Не смешивать обновление зависимостей с функциональным изменением.
4. После каждого стека прогонять полный release-gate из
   [IDE-CAPABILITY-MATRIX.md](IDE-CAPABILITY-MATRIX.md).
5. Не заменять закреплённый Cursor SDK по результату одного `npm outdated`:
   registry-тег `latest` сейчас указывает на `1.0.18`, тогда как проект осознанно
   закреплён на `1.0.28`.

Frontend: `@types/react-dom` имеет patch-обновление `19.2.4 → 19.2.5`;
`monaco-editor 0.52.2 → 0.56.0` и `typescript 5.9.3 → 7.0.2` требуют отдельной
проверки совместимости. Расширение: `esbuild 0.25.12 → 0.28.2`.

`npm audit` для frontend и `npm audit --omit=dev` для расширения не нашли
production-уязвимостей. Полный dev-аудит расширения сообщает advisory в
`undici 5.29.0`, который приходит через `@cursor/sdk` и
`@connectrpc/connect-node`. Production-сборка не поставляет этот пакет:
`runtime/build.mjs` подменяет импорт на `undici-node22-shim.cjs` и собирает
разрешённые зависимости в `dist/cursor-deps.cjs`. Риск всё равно нужно
перепроверять при каждом обновлении Cursor SDK.

## Команды аудита

```powershell
go list -m -u all

Push-Location frontend
npm outdated
npm audit
Pop-Location

Push-Location vscode-extension
npm outdated
npm audit --omit=dev
Pop-Location
```

Сетевой аудит изменяется со временем. Таблица выше становится историческим
снимком после следующего запуска и должна быть обновлена целиком, вместе с датой.
