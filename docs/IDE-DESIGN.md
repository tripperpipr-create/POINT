# Раскладка Point IDE

Эталон рабочего пространства оболочки: какие части есть у окна, какое окно
инструментов где живёт, что открывается вкладкой, что — всплывающим, и по какой
клавише. Сверено с исходниками 9 сентября 2026 года; строки, помеченные
«переезд», описывают решение, а не текущий код, — их состояние собрано в разделе
«Что уже так и что переезжает».

Визуальный ориентир — современные IDE JetBrains: плотность, окна инструментов,
предсказуемое расположение и минимум украшений. Копии не делаем: у Point свои
поверхности (Помощник, Хаб агентов, Летопись), и они встают в ту же систему.

Цвета, шкалы и движение здесь не объявляются. Их источник —
`vscode-extension/ui/tokens.css` и шапка `distribution/resources/point-workbench.css`;
словарь и правила сборки CSS — [RPG-DESIGN-SYSTEM.md](RPG-DESIGN-SYSTEM.md).
Что из перечисленного доведено до рабочего маршрута с регрессией — в
[IDE-CAPABILITY-MATRIX.md](IDE-CAPABILITY-MATRIX.md).

## Правило размещения

Одно правило отвечает на вопрос «куда это положить», и все таблицы ниже — его
следствие:

- **Рейка и боковая панель — навигация.** Дерево, список, структура: то, из чего
  выбирают, куда пойти. Живёт слева, открыто подолгу, узкое.
- **Нижняя панель — поток.** Вывод, лог, сессия, история: то, что течёт во
  времени и читается широкими строками. Открывается под задачу и закрывается.
- **Вкладка редактора — документ.** То, что требует ширины и читается целиком:
  файл, сравнение версий, Хаб агентов, статистика, стартовая страница.
- **Всплывающее — выбор.** Действие в один шаг: найти, перейти, переключить.
  Не занимает места, закрывается по Escape и возвращает фокус.

открывают под конкретную задачу. Поведение узкого окна собрано в блоке «Узкое
окно и покой» `distribution/resources/point-workbench.css`.

## Карта окна

```
+-----------------------------------------------------------------------+
| [] = [проект v] [ветка v]     поиск...    [цель v] > %  []  ?  - [] x  |  титульная полоса
+--+----------------+---------------------------------+----------------+
|[]|                |  main.go x   README.md x        |                |  вкладки редактора
|Y |   Проект       +---------------------------------+   Помощник     |
|= |   (дерево)     |  main.go > main()               |   Point        |  крошки
|  |                |                                 |                |
|--|                |            редактор             |                |
|Q |                |                                 |                |
|> |                |                                 |                |
|% |                |                                 |                |
|! |                +---------------------------------+----------------+
|D |                |  ЗАПУСК                          (действия окна) |  шапка окна низа
|L |                |  цель · консоли · вывод                          |
|T |                |                                                  |
+--+----------------+--------------------------------------------------+
| ядро · индекс         строка 1, столбец 1  UTF-8  LF  Go  !0 x0  вести |  строка состояния
+-----------------------------------------------------------------------+
```

Верхняя группа рейки — окна боковой панели, нижняя — окна нижней панели.
Разделены волоском; порядок внутри каждой задан номером клавиши.

## Полосы ярлыков

**У окна инструментов обязан быть ярлык, и окна без ярлыка не бывает.** Это не
украшение: окно, которое видно только по памяти на сочетание клавиш, для
большинства не существует вовсе. Закрытая нижняя панель не должна уносить с
экрана Запуск, Отладку, Проблемы, Поиск, Службы и Логи.

Поэтому левая рейка несёт две группы значков: сверху окна боковой панели, снизу
— окна нижней панели. Нажатие открывает своё окно, повторное нажатие по
активному закрывает панель. Подсказка называет окно и его клавишу («Запуск ·
Alt+4») — номер приходит из `lookupKeybinding`, а не переписывается руками, и
поэтому не может разойтись с `package.json`.

Из этого правила следует и второе: **ряда вкладок в шапке нижней панели нет**.
Полный список окон живёт в рейке, и повторять его в шапке значило бы завести
второе место для одного выбора — ту же ошибку, что была у терминала. Шапка
панели показывает имя активного окна и его действия.

Счётчик окна (ошибки у Проблем, ход у Запуска) живёт на ярлыке: вкладку видно,
пока панель открыта, а ярлык — всегда, и молчащий ярлык вернул бы ту же
слепоту, ради которой полоса и заведена.

При нехватке высоты полоса прокручивается, а не сворачивается в «Ещё…»: восьми
окон мало для второго уровня выбора, а прокрутка не прячет ни одного. Уезжает
при этом полоса, а не шестерёнка — та стоит вне её.

## Титульная полоса

Три группы и ничего сверх них:

- **Слева** — значок окна, «Частые действия» (`Alt+Shift+A`), чип проекта, чип
  ветки. Чип ветки отвечает на вопросы, с которых начинается работа с Git:
  точка несохранённого, счётчики входящих и исходящих, значок облака у
  неопубликованной ветки. Нажатие раскрывает список с шапкой, плитками и рядом
  действий.
- **По центру** — строка поиска (`Ctrl+N`, двойной Shift). Сжимается первой.
- **Справа** — чип конфигурации запуска, «Запустить», «Отладка», кнопка
  раскладки «Рабочее пространство», справочник клавиш, системные кнопки.

Чип конфигурации показывает имя текущей цели и открывает выбор по нажатию. Имя
приходит контекстным ключом `point.runConfiguration` от расширения — тем же, из
которого цель рисуется в окне «Запуск», поэтому две надписи не могут разойтись.

Геометрия полосы одна на все её элементы: один рост, один радиус, наведение —
мягкая подложка без рамки. Рамку носит только кнопка запуска — единственное, что
и должно выделяться.

## Окна инструментов слева

| Окно | Клавиша | Содержимое | Чем сделано |
| --- | --- | --- | --- |
| Проект | `Alt+1` | дерево файлов активного корня | Explorer Code-OSS |
| Коммит | `Alt+0` | изменения, полка, коммит и отправка | вебвью `pointGit` |
| Структура | `Alt+7` | символы активного файла деревом | Outline Code-OSS |

Рейка — только значки: подписи съедали бы ширину, а список короткий и запоминается
по месту. Активное окно помечено полосой слева. Шапка панели: имя окна, действия
окна справа, «Ещё…» и кнопка скрытия.

Окно файлов подписано в панели «Проект», но в подсказке рейки и в меню оно
зовётся «Инвентарь» — так его называет
[RPG-DESIGN-SYSTEM.md](RPG-DESIGN-SYSTEM.md). Два имени у одного окна — долг, и
он записан здесь, а не замолчан: снимать его нужно решением о словаре, а не
правкой раскладки.

Структура — своё окно, а не вьюшка внутри Проекта: два дерева в одной панели
спорят за высоту, и символы файла тонут под деревом папок. Список символов
всплывающим окном никуда не делся — `Ctrl+F12`, когда нужен один переход, а не
постоянно открытая карта файла.

«Найти в файлах» в боковой панели нет намеренно: результаты поиска — поток, и
читаются они широкими строками. Окно живёт внизу (`Alt+3`).

## Вкладки нижней панели

| Вкладка | Клавиша | Содержимое | Чем сделано |
| --- | --- | --- | --- |
| Найти в файлах | `Alt+3` | текстовый поиск и замена по корню | Search Code-OSS |
| Запуск | `Alt+4` | текущая цель, выбор конфигурации, список консолей | вебвью `pointRun` |
| Отладка | `Alt+5` | стек, переменные, наблюдения, точки останова, консоль | Code-OSS |
| Проблемы | `Alt+6` | ошибки и предупреждения активного корня | Code-OSS |
| Службы | `Alt+8` | базы данных и серверы SSH | вебвью `pointServices` |
| Логи | — | журнал ядра и диагностика | вебвью `pointLogs` |
| Выходные данные, Терминал, Порты | — | штатные окна Code-OSS | Code-OSS |

Окна открываются ярлыком в рейке или клавишей; ряда вкладок в шапке нет (см.
«Полосы ярлыков»). Шапка показывает имя активного окна прописными мелким кеглем
и его действия справа.

Отладка — одно окно, а не два: переменные, стек, наблюдения, точки останова и
консоль отладки стоят в нём рядом по горизонтали. Отдельной вкладки «Консоль
отладки» нет — пустой контейнер прячется сам.

Окно «Запуск» управляет запуском, но не показывает его вывод. Вывод идёт в
консольный канал («Квест», «Сборка», «Тесты»), а канал открывается **вкладкой
редактора** по `Alt+F12`. Так он остаётся на виду, когда окна инструментов
скрыты по `Ctrl+Shift+F12`, и делится на группы рядом с кодом, как обычный файл.
Поведение закреплено регрессией `scripts/test-point-console-channel.ps1` —
менять его ради буквы канона не станем.

«Службы» собирают базы и серверы в одно окно двумя секциями: по отдельности это
два редко открываемых значка, вместе — один ответ на вопрос «что у проекта
снаружи». Docker и список процессов остаются широкими поверхностями и
открываются из «Частых действий»: им нужна ширина, а не узкая секция.

## Правая панель

Одно окно — диалог Помощника Point (`Ctrl+Alt+;`), по умолчанию 380px. Внутри:
лента, поле ввода с контекстом (файл, выделение, ошибка) и действия ответа.
Рейка правой панели остаётся, но с одним значком: пять значков там появились
потому, что инструментам не было другого места, а не потому, что они там нужны.

Хаб агентов и Ростер открываются вкладками редактора, а не панелью: это
документы во всю ширину.

## Область редактора

- **Вкладки файлов** — активная помечена линией, изменённая точкой, закреплённая
  кромкой. Длинное имя режется многоточием, полный путь живёт в подсказке.
- **Строка навигации** — крошки под вкладками, `Alt+Home` ставит на них фокус.
- **Поле** — номера строк, точки останова, маркеры изменений, сворачивание,
  значок запуска у точки входа.
- **Обзорная линейка справа** — ошибки, предупреждения, совпадения поиска.
- **Разделение** — справа, снизу, отдельным окном; возврат к одному редактору.
  Всё это в меню «Рабочее пространство», а не отдельными кнопками в полосе.
- **Пустое состояние** — водяной знак с тремя действиями: открыть проект,
  поиск везде, спросить Помощника.

Вкладками редактора открываются полноэкранные поверхности Point: Хаб агентов,
Подключения, Статистика, Летопись, Главная, сравнение версий и консольные
каналы.

## Подключения и выбор модели

Подключение — это адрес, ключ и каталог моделей одного провайдера. Их может быть
сколько угодно: рабочий ключ, личный, локальный сервер, Claude Code на этой
машине. Живут они в своём окне — вкладке редактора «Подключения», — потому что
это каталог: список карточек, форма и перечень моделей, и всё это читается
целиком. Внутри Хаба агентов, где они стояли раньше, за сменой модели надо было
идти в агентов.

**Ключ хранится в SecretStorage IDE, а не в настройке.** В файлах проекта, в
хронике и в ответах ядра остаётся только ссылка. Помощник, Мастер и агенты
ссылаются на подключение по идентификатору и берут из него модель — копии ключа
у них нет.

**Модель выбирается в разговоре, а не в мастере настройки.** В шапке разговора с
Помощником и с Мастером стоит чип «подключение · модель»; нажатие раскрывает
список сохранённых подключений с их моделями. Чип занимает то место, где имя
модели уже стояло, — у Помощника это была строка «модель подключена», у Мастера
кнопка «Настройки мастера»: то же имя четвёртым местом ничего не сообщает, но
занимает строку.

Выбор **сохраняется**, а не действует «на этот разговор»: ядро читает
сохранённую настройку и модель в запросе не принимает. Список говорит об этом
прямо — смена платного ключа не должна быть неожиданностью. Модель на отдельный
разговор и раздача моделей агентам в автоматическом режиме потребуют работы в
ядре и здесь не описаны.

Вместе с подключением уходят его адрес и вид провайдера: оставь их прежними — и
ядро пошло бы к старому серверу под новым ключом.

## Строка состояния

Слева направо: состояние ядра Point, индекс, позиция курсора, кодировка и конец
строки, язык, счётчики ошибок и предупреждений, ветка, уведомления. Поверх —
полоса хода при индексации, задачах и прогонах агента.

Цель указателя в строке состояния — не меньше 24px по обеим сторонам. Это не
украшение: замер живого окна дважды находил здесь счётчики уже порога.

## Клавиши окон

`Alt+0` Коммит · `Alt+1` Проект · `Alt+3` Найти в файлах · `Alt+4` Запуск ·
`Alt+5` Отладка · `Alt+6` Проблемы · `Alt+7` Структура · `Alt+8` Службы ·
`Alt+9` История Git · `Alt+F12` Консольный канал.

`Alt+2` свободен, и намеренно. Закладки в JetBrains — окно, но у Point они живут
всплывающим списком по `Shift+F11` и постоянного места в рейке не окупают.
Занять номер «на будущее» значило бы обещать окно, которого нет: пустое нажатие
хуже незанятой клавиши.

Хаб агентов — `Ctrl+Alt+I`, Ростер — `Ctrl+Alt+Shift+I`. Из ряда `Alt+N` Хаб
убран: этот ряд принадлежит окнам инструментов, а Хаб открывается вкладкой
редактора.

Остальные клавиши редактора и навигации канонические: `Alt+F7`, `Shift+F6`,
`Ctrl+Alt+L`, `Ctrl+Alt+O`, `Shift+F10`, `Shift+F9`, `Ctrl+E`, `Ctrl+B`.
Источник истины по всем сочетаниям — `vscode-extension/package.json`.

## Режимы

- `Ctrl+Shift+F12` — скрыть окна инструментов и вернуть их прежнюю видимость.
  Снимок раскладки действует до восстановления в текущем сеансе.
- Zen-режим — через палитру и «Частые действия».
- Отдельное окно для вкладки редактора и для проекта — через «Рабочее
  пространство».

Поведение окон и клавиатуры подробнее — [ide-workspace-controls.md](ide-workspace-controls.md).

## Рамка окна инструментов для вебвью

Git, Запуск, Службы, Логи и Помощник — вебвью, и они обязаны выглядеть как одно
семейство с нативными окнами. Общая рамка — шапка с именем и действиями, тело,
пустое состояние, состояние ошибки, состояние «нет связи с ядром» — собрана
один раз в `vscode-extension/ui/client/tool-window-frame.js`; стили к ней —
`ui/layers/15-tool-window.css` и `ui/layers/96-tool-windows.css`.

Базы и Серверы открываются и окном нижней панели, и вкладкой Хаба. Шапку
выбирает рамка: в окне — шапка окна, в Хабе — заголовок страницы. Переходы по
вкладкам Хаба внутри окна не показываются: там этих вкладок нет.

«Службы» держат Базы и Серверы двумя секциями бок о бок — в нижней панели
Code-OSS кладёт вьюшки контейнера по горизонтали, и это ровно та форма, которая
нужна: слева выбор, справа подробности.

Инлайновые стили в вебвью не работают: CSP без разрешения на них выбрасывает
атрибут, и стенд обязан нести тот же CSP, иначе покажет то, чего пользователь не
увидит.

## Осознанные отступления от JetBrains

- **Закладки — всплывающее, а не окно.** Причина выше.
- **Консольный канал — вкладка редактора, а не нижняя панель.** Запуск, сборка
  и тесты читаются рядом с кодом, переживают скрытие окон инструментов и
  делятся на группы, как файлы. Штатный терминал Code-OSS внизу при этом
  остаётся доступным.
- **История Git — вкладка редактора, а не окно внизу.** В JetBrains журнал
  живёт внизу узкой лентой. У Point он один на всю ширину: граф, поиск по
  сообщениям и содержимое коммита рядом. Это документ, и место ему во вкладке
  редактора (`Alt+9`). Окно «Коммит» слева историю не дублирует — там только
  текущие изменения и полка.
- **Правая панель отдана Помощнику целиком.** Это ближе к AI Assistant, чем к
  классической правой рейке JetBrains, и соответствует тому, ради чего Point
  существует.
- **Плавающих и открепляемых окон инструментов не делаем.** Code-OSS даёт
  перенос в отдельное окно и перемещение между сторонами; полноценные режимы
  JetBrains потребовали бы своей системы раскладки поверх чужой.

## Как проверять

Раскладка проверяется на живом окне, а не инъекцией стилей: `point-*.css`
правит чужую разметку Code-OSS, и подделать её страницей значит завести копию,
которая разойдётся с апстримом.

```powershell
node scripts/check-shell-tokens.mjs
node scripts/check-shell-scales.mjs
powershell -File scripts/test-point-workbench-design.ps1 -Scenario idle
powershell -File scripts/test-point-workbench-design.ps1 -Scenario file
powershell -File scripts/test-point-workbench-design.ps1 -Scenario panel
powershell -File scripts/test-point-workbench-design.ps1 -Scenario palette
powershell -File scripts/test-point-workbench-design.ps1 -Scenario nested
node scripts/verify-point-deploy.mjs
```

Правка оверлея доезжает до окна только полной пересборкой Code-OSS: сборка
установщика оболочку не пересобирает. Принятые отступления аудита оболочки
лежат в `scripts/lib/shell-accepted.json` — каждое с причиной.
