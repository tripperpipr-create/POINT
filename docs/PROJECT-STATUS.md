26 сентября разобраны два живых квеста на llmux (Qwen3.8-27B) в проекте `systemio`: «Go-сервис с /health, PostgreSQL и docker compose» (`blocked`) и последовавшая правка «заменить самописный протокол на pgx» («готово с ограничениями»). Найденные причины и что изменено:

- **Сеть задания.** Хосты реестров добавлялись только для Symfony. Go-заданию досталась одна `docker.io`, и планировщик велел исполнителю «use only the Go standard library» — так появился рукописный протокол PostgreSQL с ошибкой в порядке байтов. Теперь реестры языка из задания или манифеста попадают в карточку сами (`masterNetworkGrantsV2`, `environment.RegistryHosts`).
- **Планировщик.** Он получает `executionEnvironment`: Docker в песочнице, хосты, критерии, которые проверяет хост. План отклоняется, если стадия поручает исполнителю Docker там, где его нет, или ограничивает его стандартной библиотекой без решения человека. Причина отказа передаётся во вторую попытку.
- **Навыки Мастера.** Драйвер — отдельное решение с де-факто стандартной библиотекой. Поправка человека становится предложением памяти.
- **Проверки на хосте.** Добавлены поля JSON (`expectJson`) и сценарий сбоя зависимости с восстановлением: «база упала» больше не ручной критерий. Занятый порт называет владельца. Итог называет проваленный критерий, а не «acceptance, acceptance».
- **Самообучение.**
  - `fmt.Sprint(nil)` = `"<nil>"` делало все выученные навыки одним семейством, и откат регрессного навыка был запрещён — канарейка заклинила (21 раз в журнале). Исправлено, цикл оценки больше не обрывается на первой ошибке.
  - Сбой ревизует навык восстановления своей категории вместо нового, у агента не больше пяти выученных навыков.
  - Навык проекта без базы доказывается тремя чистыми квестами.
  - Бюджет обучения Мастера не ограничивает бесплатный рантайм, свежие задания обучения идут раньше отложенных.
- **Память.** Предложение памяти показывается под ответом, который его сделал.

- **Остановка ядра посреди запуска.** Запуск, прерванный остановкой ядра, больше не становится «blocked · context canceled»: квест встаёт на паузу с причиной «Ядро перезапустилось». Волна 1б (по этому прогону):

- **Отказ запуска не теряется.** Решением человека считаются только статусы, которые ставит человек. Отказ пишется в ленту. Без Docker запуск не тратит время на план: квест встаёт на паузу «Ждёт Docker Desktop», ядро само замечает возвращённый демон, и расширение продолжает квест с ключом из SecretStorage.
- **Чистый стенд проверки.** Проверки на хосте идут в собственном Compose-проекте квеста (`-p point-…`), начинаются с `down -v` и всегда им заканчиваются. Работающее приложение по политике доставки поднимает профиль уже в проекте человека. При провале в доказательство попадают состояние и хвост журнала контейнеров, строки с ошибками — в карточку. Запрос к сервису ждёт до 10 с вместо 3.
- **Попытки вместо тупика.** Проваленная на хосте проверка, которую может исправить код, не выносит вердикт, пока есть попытки (`maxAttempts`, по умолчанию 3). Квест получает отчёт — что ждали, что увидел хост, что сказали контейнеры. Отчёт идёт планировщику новой попытки и в командный ящик исполнителей. Отказы среды, например занятый порт, попытку не запускают.
- **Вердикт окончателен.** «Продолжить» после вердикта отказывает с указанием пути — новая версия наряда через Мастера, — и карточка эту кнопку не показывает. Квест с завершённым Flow без вердикта при продолжении проходит пропущенную проверку. При старте ядра застрявший квест возвращается к своему вердикту, а Flow — к `completed`.
- **Окно контекста** расширяется на пути запуска, после привязки модели этапа. Окно маршрута наряда берётся из справочника моделей.
- **Инструкции этапов** bootstrap и accept не называют PHP. Приёмка знает, что проверки на хосте выполняет Point после доставки.
