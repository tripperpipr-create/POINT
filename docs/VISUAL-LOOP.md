# Визуальная петля

Живой runbook для Point `1.2.2`, проверен 2 сентября 2026 года. Если число
поверхностей меняется в `build-hub-preview.js`, обновляйте команды и ожидаемые
замеры здесь в той же правке.

Смоки проверяют, что нужная строка есть в разметке. Они не видят, что колонка не
поместилась, что прокрутка заперта, что кнопка «Дальше» ушла на 1150px ниже
экрана. Онбординг был сломан ровно так: все тесты зелёные, пользоваться нельзя.

Здесь — способ посмотреть на интерфейс, не собирая установщик.

## Один экран

```powershell
node scripts/render-hub-surface.js onboarding                     # обзор
node scripts/render-hub-surface.js onboarding companion-config    # конкретный шаг
node scripts/render-hub-surface.js onboarding welcome fresh       # первый запуск, замки на месте
```

Скрипт прогоняет настоящий `media/main.js` в том же поддельном окружении, что и
смоки, и выкладывает полученную разметку в страницу с боевым CSS. Шаг задаётся
через сохранённое состояние webview: половина шагов заперта, кликами до них не
дойти.

## Все шаги сразу

```powershell
node scripts/build-onboarding-board.js 1100x720 > build/preview/board-1100.html
node scripts/build-onboarding-board.js 900x640  > build/preview/board-900.html
```

Каждый шаг лежит в коробке размером с настоящую панель редактора. Ширина панели
не равна ширине окна — при окне 1100px панель бывает 636px, а её левая колонка
347px, и медиазапросы по окну про это не знают.

## Замер вместо глаза

Три вещи глаз не ловит, а в отдельном окне они решают всё: уехала ли колонка за
правый край, стоит ли содержимое раздела на том же левом краю, что крошка над
ним, и читается ли самая мелкая надпись. Первое маскируется вертикальной
прокруткой, второе заметно только при переключении разделов, третье не
измеряется глазом вовсе.

```powershell
node scripts/build-hub-preview.js                       # 35 поверхностей в build/preview
cd build/preview; python -m http.server 8791 --bind 127.0.0.1
# в другом окне:
& "$env:ProgramFiles\Google\Chrome\Application\chrome.exe" --headless=new --remote-debugging-port=9333 about:blank
node scripts/audit-hub-layout.mjs http://127.0.0.1:9333 http://127.0.0.1:8791
```

129 замеров: 34 поверхности на ширинах 1600, 1280, 1024 и 860, а окна
инструментов и компаньон — на своих размерах. Контраст считается
против фактически видимого фона, а не по токенам: правило может поставить тусклый
текст на плашку, которой в палитре нет, и `ui/contrast.mjs` об этом не узнает.
Так нашлись счётчик рейки с контрастом 2.5 при пороге 4.5 и три колонки Ростера,
запрашивавшие 660px там, где после рейки остаётся 624.

`build-hub-preview.js` заодно ловит падение отрисовки: упавшая поверхность — это
чёрный экран вкладки, и молча пропущенная страница выглядит как успех. Так
обнаружился Арсенал, падавший на проекте без своих инструментов.

Раскладки, где левый край другой по замыслу — сплит очереди решений, история по
файлу и центрированный диалог с Мастером, — перечислены в самом скрипте.

## Посмотреть

Файловый протокол браузерная панель обслуживает снимком, поэтому нужен сервер:

```powershell
cd build/preview; python -m http.server 8777 --bind 127.0.0.1
```

Дальше — `http://127.0.0.1:8777/board-1100.html`.

## Живой стенд

```powershell
node scripts/build-live-harness.js > build/preview/live.html
```

`main.js` исполняется в настоящем браузере: клики настоящие, ошибки выводятся на
экран, а расширение подменяется заглушкой, которая **отвечает** на запросы —
без ответов цикл «отрисовка → запрос → ответ → отрисовка» не воспроизводится.
Страница сама заходит в Гильдию и пишет вердикт в `window.__verdict` и заголовок.

Проверено на настоящей поломке: со сломанным кэшем — 1605 запросов годности,
с исправленным — 2, по одному на агента.

Смоки из `scripts/` этого не видят: они кликают синтетически, вызывая обработчик
напрямую, и ответов расширения у них нет.

## Чего доска не видит

Коробка на доске имеет размер панели, но `@media` смотрит на окно браузера. При
окне 1200px правила для узкой панели не срабатывают, и доска показывает
переполнение, которого в настоящем webview нет — там окно и есть панель.

Проверено на Гильдии: доска показала третью колонку за краем при 900px, а при
честном окне 900px вёрстка сама переходит в две колонки и переполнения нет.

Поэтому: доска — для беглого обзора всех экранов сразу, одиночная страница с
окном нужного размера — для любого вывода про узкие ширины.

## Что мерить

Глаз ловит не всё, поэтому полезно спросить страницу напрямую:

- `foot.getBoundingClientRect().bottom > pane.bottom` — кнопки шага ниже экрана;
- `el.scrollHeight - el.clientHeight` на прокручиваемом элементе — есть ли что
  прокручивать (ноль при длинном содержимом означает, что высоту держит не он);
- `el.scrollWidth - el.clientWidth` при `overflow: visible` — содержимое вылезает
  за колонку и уходит под соседнюю.

Так были найдены: блочный `.hall-body`, из-за которого `flex: 1` у раздела молча
не работал; жёсткие `140px 160px 42px` в ряду настройки, вылезавшие из колонки
347px; и `<strong>` в гриде из двух колонок, ломавший «ai-ide» на «ai-» и «ide».
