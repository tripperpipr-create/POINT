# Единое пространство Git

Ожидаемое поведение: Git работает без сервисного подключения. Компактная панель показывает настоящий index и рабочие изменения; вкладка редактора объединяет историю, локальные операции, ревью и CI. Изменяющее действие всегда адресовано одному явно выбранному репозиторию. Ручной коммит включает только index; автоматический коммит задачи ограничен её файлами и сохраняет подготовленные пользовательские blobs.

Владельцы поведения:
- `internal/gitflow`: локальные команды, статус, ревизия, родительские связи истории, координация записи.
- `internal/app/git_*.go`: идентичность workspace/repository, создание репозитория, помощь и доставка задач.
- `internal/forge`: общие модели, возможности и контракт провайдера.
- `internal/integrations/gitlab/rest_*.go`: REST, ограничения вывода, секреты, ревизии и совместимость старого клиента.
- `vscode-extension/git-workbench-controller.js`: панель и диалоги локальных действий.
- `git-workspace-controller.js`: вкладка редактора, подключение и связь remote.
- `git-review-editors.js`: штатный diff, комментарии редактора и документы CI.
- `ui/client/git-workspace-ui.js`, `git-views.js`, `ui/layers/96-tool-windows*.css`: интерфейс на существующих токенах Point.

Два уровня интерфейса связаны: старые команды «Летопись» и «GitLab» открывают историю и ревью общей вкладки. Git-панель начинает с изменений; вкладка восстанавливает экран, выбранный репозиторий и черновики. Index и рабочая версия одного файла показаны отдельно. Вкладка включает граф по parent hashes, фильтры сообщения/автора/пути, сравнение ревизий, ветки, теги, remotes, stash и продолжение операций. Diff и конфликты открываются механизмами IDE.

GitLab поддерживает несколько серверов/аккаунтов. Автосвязь использует remote URL; неоднозначность требует выбора. Ручная связь и отключение относятся к конкретному repo/remote. Импорт прежнего подключения сохраняет secretRef; старую ручную workspace-связь применяем только при единственном репозитории. Для неоднозначного проекта связь выбирается заново. Новая конфигурация хранит только ссылки на секреты; host хранит значения в SecretStorage, ядро держит их в памяти.

Ревью: проектная и личная очередь, создание и редактирование MR, выбор ревьюеров среди участников, diff, общие и построчные комментарии, ответы, разрешение нитей, одобрение/снятие и merge. Pipeline, этапы, jobs, логи и повтор доступны в «Проверках». GitLab самостоятельно подтверждает права и правила merge; интерфейс показывает доступность и причину отказа.

Ревизия локального снимка учитывает index, HEAD, ветку, refs, remotes, операцию и содержимое изменённых файлов. При изменении MR автоматическое обновление оставляет показанную ревизию и требует ручного обновления перед записью. Активная карточка опрашивается каждые 30 секунд, очередь — каждые 60; скрытые поверхности не опрашиваются. Черновики сохраняются при ошибках. Внешние записи с неизвестным результатом автоматически не повторяются.

AI-помощник не получает инструментов: возвращает текст/патч по ограниченному входу. Предложение показано отдельно и связано с ревизией. Применение текста меняет только черновик; применение патча проверяет исходную ревизию и не готовит изменения автоматически. Публикация и merge выполняются кнопками пользователя. Автоматическое AI-ревью отсутствует.

Критерий готовности остаётся живым: установленная Point должна пройти index → commit → push → MR → построчный комментарий → ответ → разрешение → approve → merge на GitLab владельца. Проверки исходников не заменяют эту приёмку. До неё интерфейс и новый REST-контур считаются кандидатом; на рабочих секретах или репозиториях внешние записи в рамках разработки не проверялись.

Профильные проверки:
- настоящие временные Git-репозитории: частичный index, обратный патч, новые файлы, Unicode, отсутствие финального newline, коммит задачи, изменение редактором, граф merge;
- два вложенных репозитория, два аккаунта на одном сервере, отдельные привязки и отключение, чужие workspace/root/secret;
- REST-fixture: старая ревизия, triple-SHA комментария, существующий MR, read_api, пагинация и неизвестный результат записи;
- UI-smoke: адресация действия, отдельные staged/working строки, черновик после обновления, связи родителей в графе.

Отложенные возможности из утверждённого плана: интерактивный rebase, reflog, управление worktrees, специальные UI для LFS/submodules, параметризованный CI/артефакты, GitHub, магазин и публичный SDK. Базовые команды продолжают работать через Git.

Браузерная проверка: `node scripts/render-git-workspace.mjs`. Требуется установленный Playwright (или `POINT_NODE_PACKAGES` с каталогом доступных пакетов). Стенд загружает production bundle и сохраняет fixtures в `build/preview/git-workspace`: широкая и узкая панели, история, MR, обсуждения и проверки. Он проверяет отсутствие горизонтального переполнения, сохранение ввода и фокуса после обновления. Это не запуск расширения в Code-OSS.

Подключение native comments опирается на [официальный Comment API sample Microsoft](https://github.com/microsoft/vscode-extension-samples/tree/main/comment-sample): команда отправки получает CommentReply, команда нити — CommentThread. Меню и аргументы сверены с примером; поведение установленного редактора требует отдельной живой приёмки.
