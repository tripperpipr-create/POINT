# Надёжность и скорость квестов — 1 октября 2026

Ожидаемое поведение, зафиксированное до правки: утверждённый `dependencyPlan` готовит окружение исполнителя и каждую чистую независимую проверку один раз перед пакетом команд. Установка npm/Go/Composer отделена от scaffolding. Ошибка подготовки останавливает пакет, сохраняет реализацию и не запускает исправление кода моделью. Готовность реализации и независимая приёмка показываются отдельно.

Границы изменения: WorkOrder/TaskBrief, анализ вложенных манифестов, запуск исполнителя, pre-accept/Accept, диагностика и completion, утверждаемые поправки этапа, журнал, отчёт времени, сокращение старого контекста и отображение в Hub. Существовавшие изменения рабочего дерева сохранены. Глобальные defaults `bind` и `shadow` сохранены, модель сравнительных квестов — Qwen3.8-27B.

## Реализация

- Совместимое необязательное поле `dependencyPlan`, версия `1`, проекты с относительным `cwd`, менеджером, командами, манифестами и ожидаемыми путями. `SetupCommand.cwd` также необязателен. Исторические наряды и digest предложений без нового поля сохраняются.
- План определяется по каталогам критериев и ближайшим манифестам, включая `lk-backend/source`. npm использует lock и `--include=dev`, Go проверяет модули и восстанавливает vendor, Composer устанавливает lock с require-dev. Генерация проекта остаётся в setup.
- Одна общая подготовка для исполнителя и чистых системных проверок; утверждённые сетевые ограничения сохраняются. После каждой установки проверяется digest переносимых исходников/lock; диагностируются конкретные изменённые пути или ошибка аудита.
- Подтверждённое отсутствие объявленных `typescript`, `ts-jest`, `@eslint/js` — ошибка окружения. Настоящие ошибки TypeScript остаются ошибками реализации. Неудачная подготовка не тратит модельные циклы исправления и не публикует `accepted_after_revision`.
- Для восстановления применяется подписанное digest предложение поправки через существующие stage-retry API. Автоприменение запрещено. Утверждённый исходный наряд остаётся неизменным; поправка действует для этого квеста. Повтор Accept сохраняет законченные этапы.
- Reuse допускается только для успешной независимой проверки с совпадающими деревом, образом, правилами переносимости, сетевой политикой/hosts, эффективными критериями и fingerprint плана/манифестов. Регрессии проверяют shadow, reuse и инвалидирование. На отдельной копии восстановленного результата живые shadow и затем on прошли; глобальное включение в пользовательском процессе не выполнено.
- npm/Go download-кеши разделяются между этапами, зависимости устанавливаются в отдельной копии/томе проверки. Composer download-кеш добавлен исполнителю; независимая приёмка использует отдельный кеш, поскольку Composer lock не гарантирует integrity всех архивов. Недоказанное состояние кеша в событиях — `unmeasured`.
- Старые раунды контекста сжимаются через существующую replayable memory при рабочем размере около 64k; утверждённый стабильный ввод и последние раунды сохраняются. Агенту указано использовать автоматический финальный пакет, оставляя ручные проверки для локальной отладки.
- События подготовки и каждой системной проверки имеют корреляцию квест/Flow/этап/execution/run. `point-perf-report` использует границы Flow, включает deterministic Accept и не складывает вложенные command/audit тайминги с tool time.

## Сравнение скорости

Командный пакет ускорился с медианы 598,593 с до 33,019 с (примерно 18 раз); вместе с созданием окружения — с 614,920 с до 80,912 с (7,6 раза). Все пять пакетов каждого режима прошли, digest совпал. Командное сравнение bind/volume фиксирует исходники сохранённого writer, один digest образа, одинаковые лимиты и оригинальные три критерия. Для каждого режима выполняются пять пакетов `npm ci + typecheck + Jest + lint` и пять команд `true` с аудитом. Итоговые значения и ограничения публикуются в [отчёте сравнения](perf/quest-dependencies-bind-volume-2026-10-01.md).

Для трёх полных квестов на режим добавлен opt-in `TestDependencyQuestBenchmarkLive`: read-only SQLite backup, отдельные рабочие каталоги/БД, одинаковый baseline и три неизменяемых проверенных test suites, Qwen3.8-27B без fallback, одинаковые образ/критерии/политика, сохранение evidence/таймингов и проверка фактически использованных моделей/образов. Он компилируется, но модельный запуск не выполнялся: ключ llmux отсутствует в окружении; SecretStorage пользователя не извлекался. Запуск требует локальной переменной `POINT_LLMUX_API_KEY`, `POINT_DEPENDENCY_LIVE_BENCH=1`, Docker и абсолютного `POINT_SANDBOXD_BINARY`; команда: `go test ./internal/app -run '^TestDependencyQuestBenchmarkLive$' -count=1 -timeout=7h -v`. Протокол использует baseline с фиксированными тестами, поэтому его сравнение относится к этому протоколу, а не к точному воспроизведению исходного запроса.

Остаются неподтверждёнными три полных модельных квеста на режим, медианное ускорение минимум на 30%/ориентир до 24 минут, shadow/reuse в новом полном модельном квесте и продуктовая приёмка нового потока. До этих результатов автоматический rollout volume/reuse не выполняется; глобальный default сохранён.
