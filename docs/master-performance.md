# Скорость Мастера: первый этап

Ожидаемый результат: повторные запросы неизменившегося проекта, включая v2, используют готовые сведения; Git-ссылка задаётся отдельно от файлового фильтра; соседние и параллельные ходы имеют независимые измерения. Границы — структурные сведения, читающие инструменты и существующий журнал событий. Динамические состояния квестов, права и доказательства проверок читаются из своих источников.

## Кеш сведений

Источник — [master_facts_cache.go](../internal/app/master_facts_cache.go). Ключ: workspace ID, нормализованный корень, имя проекта и внутреннее поколение индекса. Публикация полной/частичной сборки и инвалидирование увеличивают поколение; оно общее для FS одного корня и не добавляется в HTTP-контракт. Готовых записей не больше 16, вытеснение LRU, TTL 30 секунд для ещё не отражённых индексом внешних изменений.

Одновременные вычисления одного ключа объединены, разные проекты готовятся независимо. Отмена ожидающего запроса не отменяет работу для остальных; уход последнего ожидающего отменяет вычисление. Отменённый результат и результат, подготовленный через смену поколения, не сохраняются. Выданные срезы независимы.

## История Git-ветки

Источник — [git_tools.go](../internal/tools/git_tools.go). Примеры аргументов `git_log` для Мастера:

```json
{"revision":"origin/vue-tests","limit":20}
{"revision":"HEAD~1"}
{"repo":"cf-vue-apps","revision":"v1.0","path":"cf-vue-apps/src/main.ts"}
```

`repo` выбирает репозиторий, `revision` — единственную ревизию, `path` — существующий файловый фильтр относительно workspace. Допустимы локальная/удалённая ветка, tag, SHA и одиночное выражение. Без `revision` остаётся прежняя история HEAD. Диапазоны исключены.

Сначала локальный `git rev-parse --verify --end-of-options …^{commit}`, затем `git log` с полученным SHA. Команды запускаются аргументами без shell и сети. Неверная ревизия даёт `invalid_revision`; несуществующий путь, совпавший с Git-ссылкой, даёт `invalid_path` с подсказкой использовать `revision`. Автоматического переосмысления нет; существующий файл остаётся фильтром даже при совпадении с именем ветки.

## Точные измерения

[Контракт событий](api.md#master-turn-measurements), [агрегатор](../cmd/point-perf-report/master.go). Подготовка включает закрепление workspace, вложения v2, факты и создание хода. Полная длительность заканчивается после сохранения итогового состояния; фоновое обновление резюме за её пределами. Вызовы модели измеряются по каждой попытке `Stream`, включая повторы и исправление brief; читающие инструменты — по фактическим интервалам исполнения.

Отчёт выбирает ходы по паре workspace ID / turnId и только их круги. Время читающих инструментов — длина объединения интервалов, не сумма параллельных работ. Незавершённые измерения перечислены как неполные и не входят в медианы длительности. Старые usage-записи до начала новой инструментализации workspace группируются по паузе четыре минуты в отдельном приблизительном разделе. Исторические круги без временных меток нельзя надёжно привязать к таким группам, поэтому они не включаются.

```powershell
go run ./cmd/point-perf-report -master 10 -json
```

## Воспроизводимый benchmark

```powershell
go test ./internal/app -run '^$' -bench '^BenchmarkMasterProjectFacts10000$' -benchmem -benchtime=10x -count=3
```

100 каталогов по 100 Go-файлов, полностью готовый индекс из 10 000 файлов. `cold` очищает кеш фактов перед запросом; `repeat` использует готовую запись; `after_index_update` меняет файл и публикует инкрементальный индекс перед запросом. Создание файлов, первичная сборка и обновление индекса находятся вне измеряемого времени запроса.

Измерено 2026-10-04 на Windows amd64, Go 1.25.0, Intel Core Ultra 7 155H; 10 операций × 3 запуска. Контрольный замер выполнен после завершения остальных проверок; исходный вывод сохранён локально в build/master-performance-20261004.txt:

| Подготовка | Диапазон, мс/запрос | Медиана, мс | Память, байт/запрос | Аллокации/запрос |
| --- | --- | --- | --- | --- |
| Холодный кеш фактов | 30,26–40,02 | 33,88 | 5 703 698–5 742 999 | 46 026–46 027 |
| Повторный запрос | 0,00229–0,00308 | 0,00240 | 368 | 9 |
| После обновления индекса | 13,48–18,44 | 14,38 | 5 751 313–5 797 806 | 46 028–46 030 |

Первичная сборка индекса заняла 3226 мс отдельно от запроса. Синтетический результат подтверждает устранение повторной подготовки; он не измеряет задержку модели или ускорение полного хода, не является SLO и не заменяет живую приёмку IDE.

## Проверки и границы приёмки

Регрессии покрывают coalescing, изоляцию проектов/FS, отмену, смену поколения, TTL/LRU и независимые копии; Git-ссылки, файл, вложенный репозиторий и опасные аргументы; соседние/параллельные ходы, повтор модели, неполный ход, отбор кругов и отдельную приблизительную историю. Hub сохраняет свой статус при получении измерений. Полный Go-затвор прошёл (staticcheck v0.8.1, vet, mod verify, все тесты). Проверки документации и quality gate прошли; полный docs/extension-затвор остаётся красным только на пяти известных несоответствиях аттестации sandbox. Остальные 39 шагов extension прошли, включая Хаб 88/88 на пересобранном ядре. Новый отчёт также проверен на существующей БД Point в режиме чтения: старая история отделена от точных измерений. Подробности — в [текущем статусе](PROJECT-STATUS.md).

Живые вызовы моделей, публикация и обновление установленной IDE не входят в этот этап. Перестройка фаз Мастера, параллелизм исполнителя и состояние квестов остаются следующими задачами. Пять известных несоответствий аттестации sandbox учитываются отдельно.
