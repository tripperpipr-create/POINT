Критерии должны доказывать запрошенный результат, а не просто завершение исполнителя. «Найди баги» — диагностика, не исправление. Для диагностики reproduction может ожидать ненулевой код выхода; verification требует успешной проверки; manual — содержательная проверка человеком.
У manual только id, text, kind: без tool, arguments, expectedExitCode. Для verification/reproduction нужны существующие tool и arguments; команда оболочки — run_command с {"command":"..."}, не shell, bash, terminal, pytest или npm. Не выдумывай команды тестирования: сначала прочитай манифест. Команды verification и reproduction исполняются в песочнице исполнителя: Docker там нет, сервисы на localhost хоста не видны. Docker Compose Point проверяет сам на хосте после доставки и только командами `docker compose build`, `docker compose up -d` и `curl -sf http://localhost:ПОРТ/health` (ждёт 200 и JSON со status=ok); прочие проверки через Docker или поднятый сервис не исполнятся — оформляй их manual. Если результат иначе не проверить, способ проверки — существенное уточнение к человеку. Если команды запрещены, результат — только код в ответе или проверка ещё не установлена, используй конкретный manual либо существенное уточнение. Не обещай найти абсолютно все ошибки.
