# Changelog

## Unreleased — живой прогон и то, что он вскрыл

- Полосы прогресса показывали «готово» всегда. CSP вебвью выбрасывает атрибут
  `style=""` целиком, а ширину полос разметка задавала именно им; правило полосы
  при этом говорило только `height: 100%`, и блочный элемент занимал всю ширину
  родителя. Квест на одном этапе из семи выглядел законченным, бюджет —
  израсходованным, шкалы политики Мастера — выкрученными на максимум. Девять
  мест, и все девять врали одинаково. Открывать CSP ради них нельзя, поэтому
  величина идёт атрибутом `data-fill` с шагом в пять процентов, а в ширину её
  переводит слой `ui/layers/11-progress-fill.css` через переменную `--fill`:
  правило-ступень со специфичностью (0,1,0) проиграло бы любому `.класс > i`, а
  переменная за ширину не спорит. Запасное значение — пусто, а не полно:
  неизвестный прогресс честнее показать нулём, чем победой. Замер на собранном
  CSS: 15 % → 60 px из 400, без атрибута → 0 px вместо прежних 400.
- Двадцать семь веток кликов отдавали `undefined` вместо `true`. Цепочка
  обработчиков останавливается на первом, вернувшем `true`, и молчаливая ветка
  пускала клик дальше по всем остальным. Восемнадцать из них — с недостижимым
  `return true` строкой ниже: намерение было записано, а работал соседний
  оператор. Видимого двойного срабатывания не наблюдалось только потому, что
  имена действий пока нигде не совпадают — защита была снята, а не сработала.
  Среди починенного «Утвердить наряд», «Пауза», «Оставить всё», «Откатить всё»
  — ровно те кнопки, которые жмут на живом прогоне. Остальные девять — ранние
  выходы после показанной ошибки валидации: ветка, назвавшая причину отказа,
  тоже обработала действие. Затвор `scripts/check-click-handler-returns.mjs`
  проверен на подделке и входит в `npm run check`.

## Unreleased — Documentation and release gates

- Hub v2 + API-only cutover. Claude Code / Codex / Cursor CLI сняты: помощник и
  агенты работают только через HTTP API (Ollama, OpenAI-совместимый, Anthropic,
  Azure). В UI основной запуск — карточка наряда WorkOrder у Мастера; вкладки
  flows/workflows спрятаны за редирект. Legacy HTTP в ядре сохранён. База по
  умолчанию — `hub-v2.db`.

- Настройка помощника открывается с того шага, с которого начинается. Порядок
  шагов я поменял, а кнопка «Настроить» по-прежнему вела на «Роль»: человек
  открывал настройку, видел выбор роли и не понимал, где мозг, — а выбрав его
  через боковой список, возвращался к прежнему виду. Теперь открытие ведёт на
  «Мозг».
  И главное: теперь это проверяется поведением, а не разметкой. Новый смоук
  `smoke-companion-brain-choice.js` (44-й) проходит путь человека — открыть
  настройку, выбрать Claude Code, выбрать модель, сохранить — и смотрит, что
  ушло в ядро: провайдер `claude-code-cli`, выбранная модель, пустые адрес и
  подключение. Прежние проверки мастера смотрели на шаги и валидацию, поэтому
  три дефекта подряд (недостижимая ветка, список режимов в трёх местах, шаг
  открытия) они пропустили.

- Выбранный Claude Code перестал сползать во встроенный разбор. Список видов
  мозга был записан трижды: в санитайзере черновика мастера, в санитайзере
  онбординга и в обратном разборе сохранённой настройки. Первый я поправил, а
  два других остались на двух видах — и любой оборот (перерисовка, приход
  состояния, повторный вход в мастер) молча превращал «Claude Code» во
  «встроенный разбор Point». Теперь список живёт в одном месте
  (`COMPANION_BRAIN_MODES`), обратный разбор знает провайдера `claude-code-cli`,
  а договорённость 25 проверяет и нормализацию, и то, что список не переписали
  снова по месту: мутации ловят обе половины.

- Выбранный Claude Code больше не сохраняется как встроенный разбор. Ветка
  локального CLI в сборке настройки стояла ниже общего «всё, что не модель по
  API», и была недостижима: человек проходил мастер, выбирал Claude Code,
  настройка уходила в ядро с пустым провайдером — и чат отвечал местным
  разбором, сообщая в логе `provider=none model=none`. Ошибка в порядке двух
  условий, и заметна она только на живом прогоне: тесты мастера проверяли шаги,
  а не то, что доехало до ядра.
  Сборка настройки вынесена в `ui/client/companion-compose.js` и покрыта
  договорённостью 25, которая проверяет результат для всех трёх видов мозга —
  локальный CLI, встроенный разбор и сетевая модель. Текстовый сторож «ветка
  выше условия» я заменил на эту проверку: расположение строк — не поведение, и
  сторожить надо второе.

- Модели Claude Code называются псевдонимами последней версии. Сначала я заменил
  псевдонимы на перечень версий — и ошибся дважды: список оказался на поколение
  позади (`claude-opus-4-1` там, где CLI по псевдониму `opus` отдаёт
  `claude-opus-5` с окном в миллион токенов), и он устаревал бы молча при каждом
  обновлении CLI. Спросить у него точные имена можно только запросом к модели,
  то есть за деньги человека, а локального списка у CLI нет. Поэтому в списке
  снова `opus`, `sonnet` и `haiku` — так их описывает сам CLI («alias for the
  latest model»), и они не расходятся с ним при обновлении. Пределы Point узнаёт
  не из имени, а из первого же ответа: исполнитель сообщает окно контекста и
  потолок вместе с расходом. Каталог моделей заодно узнал пятую серию Claude —
  числа взяты из отчёта CLI, а не из головы. Версия исполнителя ушла из названия
  модели в отдельное поле: она свойство CLI, а в списке моделей ей не место.
  Регрессия `TestClaudeCLIModelsUseLatestAliases` следит, чтобы версия снова не
  просочилась в имя.

- Подключение к локальному Claude Code сохраняется. Форма перестала спрашивать
  адрес и ключ, но ядро всё равно отвечало «провайдер подключения
  "claude-code-cli" не поддерживается»: список допустимых видов в
  `internal/connections` знал только сетевые. Теперь знает и локальный, причём
  адрес и версия API у него принудительно пустые — это свойство источника, а не
  недосмотр формы, — и ссылка на секрет не заводится вовсе: пустая ссылка в
  хранилище выглядит как потерянный ключ, а ключа здесь нет. Проверено живьём:
  подключение сохраняется, а его проверка возвращает `connected` со списком
  моделей CLI. Регрессия `TestUpsertAcceptsLocalCLIWithoutURLOrSecret`, обе
  мутации её роняют.

- Форма подключения перестала спрашивать то, чего у источника нет. Мастер
  помощника я поправил, а общую форму «Связей» — нет: выбрав «Claude Code CLI»,
  человек всё равно видел «Адрес сервиса», «Версия API» и «Токен / API-ключ» и
  справедливо спрашивал, зачем это ему, если вход уже сделан в самом CLI. Теперь
  при выборе локального источника лишние поля прячутся сразу, до сохранения, а
  пояснение меняется на честное: адрес и ключ не нужны, отвечает процесс на этой
  машине, учётных данных Point не видит. Смоук
  `smoke-connection-form-local-cli.js` (43-й) проверяет обе стороны — и что поля
  возвращаются, когда источник снова сетевой.
  Первая правка при этом ничего не изменила на экране, и это оказалось не её
  виной: атрибут `hidden` вообще не прятал ничего в этой форме — правило
  `.companion-new-connection label { display: grid }` перебивало его по силе
  селектора. Так же молча висела «Версия API» у всех источников, кроме Azure,
  кому она одна и нужна: этот дефект жил в форме до всякого CLI. Теперь скрытые
  поля прячутся честным селектором (без `!important` — бюджет стилей его и не
  пропустил), а смоук сторожит само правило: код может ставить `hidden`
  сколько угодно, если разметка его игнорирует.

- Настройка помощника начинается с мозга, и мозгов теперь три. Раньше первым
  шагом была роль, а мозг — четвёртым: человек выбирал характер и навыки для
  того, чего ещё нет, а потом оказывалось, что модель не подключена. Теперь
  порядок обратный, и на первом шаге три карточки: «Модель по API», «Claude Code
  на этой машине» и «Встроенный разбор Point». У среднего ни адреса, ни ключа —
  вход человек сделал в самом CLI, — поэтому и форма другая: проверяется не
  endpoint, а сам Claude Code (`claude --version`), модель выбирается из его
  ответа, а рядом сказано, чем он платит и где проходит граница его прав.
- Расход при локальном исполнителе виден целиком. Claude Code сообщает вдесятеро
  больше, чем мы записывали: стоимость обращения, чтение и запись кэша, окно
  контекста и потолок ответа модели. На замере из 20 132 входных токенов свежими
  были десять — считать только их значит показывать вчетверо меньше правды.
  Теперь под ответом видно «Окно модели 200K, ответ до 32K», стоимость и объём
  кэша, а в «Сведениях» — те же числа словами. Деньги считаются целыми
  (стотысячные доли доллара): сложенные из дробных, они расходятся с суммой по
  строкам, и объяснить это человеку нечем.
  Лимитов подписки Claude Code в ответе не отдаёт — ни остатка окна, ни срока.
  Показываем то, что он действительно сообщил; выдумывать остаток не станем.

- Разбор собственного кода нашёл четыре дефекта в свежей связке с Claude Code —
  все закрыты.
  Ключ MCP-сессии уходил в аргументах командной строки, а их на этой машине
  читает любой процесс: подсмотренный ключ — это чужие права, и пока помощник
  только читает, но архитектура задумана под агентов, которые меняют файлы.
  Теперь конфигурация уходит временным файлом, доступным владельцу, и исчезает
  вместе с работой.
  Длинный вопрос вовсе не запускал CLI: командная строка Windows обрывается на
  32 767 знаках, а сообщение человека Point принимает до 32 КБ — вставленный лог
  съедал лимит целиком, и запуск падал до модели с невнятным «filename or
  extension is too long». Разговор теперь уходит в стандартный ввод, в
  аргументах остались флаги; системное сообщение следует туда же, когда само
  становится слишком длинным. Замер после правки: вопрос на 30 851 байт прошёл,
  ответ пришёл от модели.
  Фильтр данных выкидывал из контекста нормальный код: среди маркеров каталогов
  стояли `log` и `dump` в единственном числе, под которые попадает
  `pkg/log/logger.go` — обычное имя пакета. Теперь расширение исходника весомее
  имени папки.
  У исполнителя со своими инструментами счётчик вызовов ядра всегда ноль —
  вызовы идут по MCP мимо цикла, — и спасательный круг для сорванной формы
  ответа не включался именно там, где нужнее: на длинном вопросе Claude Code
  отвечал разметкой вместо конверта, и разговор уходил на местный разбор.
  Напоминание о форме теперь приписывается к вопросу с самого начала, а чинящий
  круг доступен и такому исполнителю.
  Заодно `GET /mcp` отвечает словами протокола вместо молчаливого 405: клиент
  пробует открыть поток событий, а здесь вызовы идут запрос-ответом.

- Ядро отдаёт свои инструменты по MCP, и права при этом не удваиваются. Модель,
  работающая по API, получает инструменты в теле запроса; локальный CLI устроен
  наоборот — свои исполняет сам, чужие принимает только как MCP-сервер. Чтобы у
  одной сущности не завелось двух разных наборов прав, сервер (`internal/mcp`)
  не знает ни про `policy.Grants`, ни про реестр инструментов: он спрашивает
  исполнителя той сущности, что открыла сессию, — тот же, который отвечает на
  обычном пути. Кто спрашивает, решает ключ сессии, а не заголовок с именем:
  ядро выдаёт ключ под сущность перед работой и закрывает вместе с ней, потому
  что переживший работу ключ — дыра в правах. Отказ по правам приходит ответом с
  `isError`, а не обвалом транспорта: исполнитель обязан объяснить причину
  человеку.
  Граница между своими и чужими инструментами проходит по существу дела, а не по
  скорости: читать и искать CLI волен сам — это быстро и ничего не меняет, — а
  всё, что меняет или рискует, идёт через инструменты Point, где записаны права
  сущности. Разрешения выдаются поимённо (`mcp__point__<инструмент>`), а не
  шаблоном: шаблон пережил бы появление нового инструмента в реестре и выдал бы
  его молча. Маршрут `/mcp` живёт под собственным ключом — общий ключ API
  открывает всё ядро и в чужой процесс не отдаётся. Регрессии на список, вызов,
  отказ, неизвестный и закрытый ключ, а также на то, что сессия открывается
  только для CLI и закрывается вместе с разговором; раздел в `docs/api.md`.
  Проверено живьём, не только тестами: ядро на этом репозитории, помощник на
  Claude Code, вопрос «найди через индекс Point, где задан companionModelBudget».
  В логе ядра — `mcp tool call subject=companion tool=search_code ok=true
  duration_ms=712`, в ответе — `internal/companion/read_tools.go` строка 157 со
  значением и местами использования. Заодно вызовы инструментов теперь видны в
  логе поимённо: чужой исполнитель зовёт их молча, и без этой записи о том, что
  смотрел помощник, узнать было неоткуда.

- Помощника можно подключить через Claude Code CLI вместо Anthropic API. Новый
  вид провайдера `claude-code-cli` отвечает локальным процессом: ключа у такого
  подключения нет и адреса тоже — вход человек уже сделал в самом CLI, и Point
  его учётных данных не видит. Ядро запускает `claude --print` в папке проекта,
  разбирает поток `stream-json` и отдаёт его обычным путём: стриминг в чат,
  подсчёт токенов, проверка конверта, бюджеты и откат работают поверх без
  изменений.
  Инструменты здесь чужие: Claude Code исполняет свои сам и наружу их не отдаёт,
  поэтому читающие инструменты Point ему не объявляются — иначе помощник ждал бы
  вызовов, которых из CLI не приходит. Вместо списка он получает границы: читать
  файлы, искать по коду и смотреть историю git можно, менять файлы, запускать
  команды и выходить за read-only git — нельзя (`--allowed-tools` перечисляет git
  по подкомандам, `--disallowed-tools` закрывает запись и сеть). Проверка связи
  для него — не запрос по адресу, а `claude --version`: список моделей у CLI
  свой. Регрессии на разбор потока, склейку разговора в один запрос и на то, что
  инструменты Point такому провайдеру не объявляются. Заодно `ProbeProvider`
  вынесен из `app.go` в `internal/app/provider_probe.go` — файл упёрся в бюджет
  строк, и правильный ответ на это тот же, что и раньше.
  Установленный CLI не считается отсутствующим только потому, что его каталога
  нет в `PATH`: установщик кладёт себя в `~/.local/bin` и точку входа прописывает
  не всегда, поэтому ядро смотрит туда само (и в `~/.claude/local`). Проверено
  живьём, а не только тестами: сквозной прогон через API ядра нашёл два пробела,
  которых юнит-тесты не видели, — настройка помощника отвергала новый провайдер
  («companion provider is not supported»), а первая версия правки выходила из
  функции раньше сохранения, и настройка возвращалась принятой, не доезжая до
  хранилища. Обе закрыты регрессиями; мутация со вторым дефектом роняет
  `TestCompanionAcceptsClaudeCLIWithoutURL` именно на чтении из хранилища.
  Установленный CLI при этом не считается отсутствующим только потому, что его
  каталога нет в `PATH`: установщик кладёт себя в `~/.local/bin` и точку входа
  прописывает не всегда, поэтому ядро смотрит туда само (и в `~/.claude/local`).
  Платить за чужую недоделку правкой системных переменных человеку незачем.

- Чужие данные больше не уезжают в модель вместе с вопросом. Поиск по индексу
  ранжирует куски по совпадению слов, и на вопрос «посмотри последние коммиты»
  лучшим куском оказался `docker/logs/logs/vote-feedback.csv` — журнал обращений
  клиентов с фамилиями, идентификаторами и текстами. Он ушёл в системное
  сообщение и на внешний шлюз; видно это стало только в логе провайдера. Прежний
  отбор берёг лучший кусок всегда, каким бы он ни был. Теперь данные не
  подмешиваются вовсе: журналы, дампы, бэкапы, таблицы, базы и ключи (`.csv`,
  `.log`, `.sql`, `.bak`, `.crt`, `.env` и соседи, а также пути внутри `logs/`,
  `dumps/`, `backup/`, `ssl/`) в автоматический контекст не попадают. Прочитать

  и вся прошлая переписка — модель отвечала словами вместо конверта, и Point
  повторял запрос целиком, чтобы получить форму. В живом логе этот исправляющий
  круг срабатывал на каждом ответе и добавлял к нему около пяти секунд и десятки
  килобайт входа. Теперь формат напоминается в том же круге, где ответ уже ждут,
  и только там: напоминание не попадает ни в переписку, ни в сохранённую
  историю, а про инструменты в нём сказано отдельно — иначе оно торопило бы
  модель отвечать вместо нужного вызова. Исправляющий круг остаётся запасным
  путём. Регрессия `TestCompanionRemindsEnvelopeInsteadOfRepairRound`: без
  напоминания кругов три, с ним — два.
- `git_diff` показывает содержимое коммита. Помощник видит историю заголовками
  через `git_log`, и на вопрос «что изменилось в этих коммитах» ответить ему было
  нечем: инструмент знал только рабочее дерево. Теперь у него есть аргумент
  `commit` — хеш, тег, ветка или `HEAD~1`. Ревизия проверяется до вызова (git
  читает опции там же, где ссылки, поэтому ведущий дефис и диапазоны отклонены)
  и разрешается в хеш: несуществующая ссылка отвечает отказом, а не пустым diff,
  который модель прочитала бы как «изменений нет». В ответе — `scope`, автор,
  дата, заголовок коммита и его изменения.
- Разговор с помощником перестал уезжать вверх при каждой реплике. Поле ввода
  получает фокус после отправки, а снимок интерфейса возвращает фокус после
  каждой отрисовки; обычный `focus()` подтягивает поле в видимую область и
  прокручивает ближайшего предка. В боковой панели это `.companion-chat-workspace`
  с `overflow: hidden` — скроллбара у него нет, вернуть прокрутку нечем, и лента
  съезжала. Замер на живом стенде: 241px за одну отправку, ноль после
  `preventScroll`. Договорённость 19 в `ui/contracts.mjs` сторожит оба места.
- Чат по логам показывает отправленное сразу. Ядро сохраняет вопрос и ответ
  одной парой в конце круга, а панель рисовала только сохранённую историю:
  человек отправлял вопрос и до ответа не видел ни своей реплики, ни признака
  работы, а при обрыве круга не оставалось и её. Теперь реплика появляется
  сразу, рядом стоит «Разбираю логи…», и она держится на экране, пока пара не
  доедет до истории.
- Кнопки «Новый чат» и «Очистить диалог» больше не выглядят одинаково: обе
  очищали ленту, а разница — архив — нигде не называлась. Теперь это «Новый чат ·
  текущий в архив» и «Удалить историю · без архива», с пояснением в подсказке.
- Помощник больше не зацикливается на инструментах. Потолок в три вызова держался
  только против модели, которая сама перестаёт просить: проверка «инструментов не
  предлагали» смотрела на весь каталог помощника, а он непуст всегда. Модель,
  продолжавшая звать инструмент после потолка, получала исполнение снова и снова —
  разговор о diff последних коммитов ушёл на 49 повторов `git_diff`, тело запроса
  выросло с 25 КБ до 335 КБ, и ответ оборвался таймаутом ядра на 90 секунде.
  Теперь смотрим на инструменты текущего круга. Регрессию держит
  `TestCompanionToolLoopStopsWhenModelIgnoresMissingTools`: со старым условием
  модель, просящая вызов всегда, вешает тест до его таймаута.
- Навыки помощника выбираются в его настройках: шаг «Навыки» встал третьим в
  мастере, отдельно от агентского конструктора. Ядро хранило `SkillIDs` и
  проверяло их с самого начала, но отмечать было негде, а `companionConfigPayload`
  не клал `skillIds` в тело запроса — выбор не доехал бы и при наличии экрана.
  Доступ экран считает по тем же группам каталога, что выдаёт ядро (`read`,
  `index`, `git`): навык с исполняющим умением не отмечается, надетый раньше
  показан с причиной и не даёт сохранить настройку до снятия, а навык вне
  текущего каталога — перенесённый или продвинутый из выученного — формой не
  снимается. Путь закреплён `scripts/smoke-companion-skill-equip.js`, а
  договорённость 18 в `ui/contracts.mjs` ловит и расхождение групп, и потерю
  `skillIds` в теле запроса.
- Живые документы сверены с Point `1.2.2`: онбординг содержит 9 шагов,
  run-configuration snapshot создаётся как `v2`, а HTTP-каталог включает все
  124 зарегистрированных маршрута.
- Введены индекс документации, актуальный технический срез, политика обновления
  зависимостей и `scripts/check-docs.mjs`, который проверяет ссылки, версии,
  API-инвентарь и число шагов онбординга.

## 1.2.2 — Companion across the IDE

- Профили SSH и подключения к БД теперь можно редактировать на месте: форма заполняется текущими host/port/path/SSL-параметрами, а пустое поле пароля сохраняет прежнюю ссылку SecretStorage. Режим редактирования закрывается только после подтверждённого сохранения, поэтому ошибка ядра не стирает введённые данные; инвариант `id + secretRef` закреплён webview-регрессией.
- SQL-консоль отпирает форму после `dbWriteRequired` и `dbQueryResult`: раньше общий anti-double-submit мог навсегда заблокировать второй запрос. Чёрноящичный portable E2E проходит видимый approval-гейт, CREATE/INSERT/SELECT/schema/test SQLite и реальный OpenSSH probe, не обращаясь к приватному состоянию webview bundle.
- Консольный канал получил отдельную runtime-регрессию: `Alt+F12` создаёт terminal editor с cwd активного проекта, именем `Point · Квест`, постоянной вкладкой и повторно использует уже открытый канал. Cold-start E2E сохраняет ленивую активацию extension host, получил отдельный 60-секундный бюджет для первого Windows-запуска и при тайм-ауте печатает состояние вкладок, терминалов, уведомлений и диалогов. Эта проверка поймала два ранних `undefined` на пустом редакторе (`getWorkspaceFolder` и `cwd`); теперь команда коротко ждёт корень проекта и имеет безопасный домашний cwd. В Хронике ядра видны точные метки начала/готовности активации и обработки terminal-команды.
- SSH-профиль теперь открывает не сырой modal с `ls -la`, а навигатор от сохранённого удалённого пути: каталоги переходят вглубь, UTF-8 файл открывается в редакторе ограниченным предпросмотром до 64 КиБ, бинарный ответ отклоняется. Путь shell-quoted, пароль приходит только одноразово из SecretStorage, неявной записи на сервер нет; сценарий закреплён отдельным smoke от корня профиля до вложенного файла.
- Индекс кода стал ограниченным и честным на монорепозиториях: максимум 100 000 элементов обхода, 20 000 файлов, 96 МБ исходников и 50 000 chunks. Достигший границы индекс остаётся доступным, но сообщает `partial` и точную причину; промах поиска не запускает тот же полный обход повторно, а инкрементальный watcher не может дорастить память сверх лимита. Статус-бар и Hub явно предупреждают о неполном охвате.
- Agent Hub получил настоящую JS-сборку. Редактируемые исходники живут в `ui/client`, esbuild создаёт единственный CSP-совместимый `media/main.js`, а VSIX не содержит исходное дерево. В отдельные модули вынесены инфраструктурные экраны БД/SSH/LLM-подключений и Git-adjacent ревью Change Sets/журнал откатов; их зависимости передаются явно. Статические контракты читают модули, а render/smoke исполняют именно поставляемый bundle.
- Полный снимок мира перестал быть платой за каждое действие. 68 вызовов `/api/bootstrap` сведены к одному холодному открытию: сохранения точечно обновляют полученный объект, а flow, run, workflow, решения, откаты, Git-патчи и действия Гильдии используют согласованные `/api/state/runtime`, `/api/state/guild` и `/api/companion/live`. Фоновый polling больше не перечитывает профили, подключения, память, историю диалогов и тысячи записей usage.
- Холодная активация расширения больше не разбирает Cursor SDK. Runtime действительно ленивый: простой старт Point делает только проверку наличия локального bundle, а 6,6 МБ кода SDK загружаются при первом статусе, входе или Cursor-запуске. Регрессия закреплена отдельно для исходников, VSIX и встроенного portable-расширения.
- Production-упаковка расширения стала компактной и воспроизводимой. Cursor SDK остаётся байт-в-байт исходным набором CommonJS-чанков, его открытые JS-зависимости собираются esbuild в один 366-КБ файл, а в `node_modules` поставки остаётся только нативный `sdk-win32-x64`. VSIX уменьшен с 561 файла (332 JS) до 70 файлов без предупреждения `vsce`; тот же артефакт собирается перед наложением Code-OSS overlay.
- Multi-root workspace перестал означать «молча работаем с первой папкой». В строке состояния выбирается активный проект Point; выбор сохраняется, прежнее ядро безопасно отсоединяется, а новое стартует по требованию. Индекс, вложения, Cursor, Problems, SCM и контекст компаньона принимают только пути выбранного корня — правка во втором проекте больше не инвалидирует индекс первого и не попадает агенту под ложным относительным путём. Добавление соседнего проекта не перезапускает живое ядро; отдельные окна по-прежнему могут держать независимые ядра разных проектов одновременно.

Заголовок задачу не заменял: он обрезан до строки для очереди решений. Теперь предложение несёт задачу дословно (миграция 18), она становится описанием квеста, а обоснование выбора отряда остаётся при отряде. Предложения, созданные до миграции, сохраняют прежнее описание, а не пустое.
- Просьба поправить предложенный квест правит его, а не создаёт второй. «Убери Разведчика из отряда» начинается рабочим глаголом, и разбор считал это новой работой: в очередь ложилось второе предложение с этим самым названием, а первое продолжало ждать — человек разбирал две записи вместо одной поправленной. Теперь модель называет идентификатор правимого предложения, и оно обновляется на месте. Права те же: состав пересобирает проверенный подбор, годность считает тот же код, решённое предложение не правится, а запуск остаётся за человеком.
- Мастер помнит собственное предложение. «А можно без него?», «почему этот агент?», «что ты предложил?» — вопросы сразу после предложения квеста, а в снимке мира у модели были только счётчики, и отвечать на них было нечем. Теперь модель видит ждущие решения предложения с их отрядом и целями и идущие квесты; решённые предложения в разговор не попадают — человека они уже не ждут.
- Разговор с Мастером ведёт его модель, а не список ключевых слов. Разбор намерения по фразам делал из диспетчера справочник: «кто есть в ростере?» он узнавал, а «Сколько есть агентов?» — нет, и отвечал той же строкой, что на «привет». По ответу нельзя было понять, разобрал он вопрос или нет. Модель получает системный промпт роли и снимок мира как недоверенный контекст; на задачу она формулирует квест — заголовок, цели, признаки готовности — и называет, кого взять.
- Права модели при этом не выросли: состав отряда проходит через тот же подбор (несуществующие агенты отбрасываются, размер режется политикой), годность считает тот же код, что и карточка агента, отказ «никто не доведёт работу до конца» перебивает любой оптимизм модели, а запуск остаётся решением человека.
- Ключ модели Мастера доходит до ядра. Без него модельный путь молча падал в откат у всех провайдеров, кроме локальных: человек настраивал модель и навсегда получал детерминированный движок.
- Видно, чем отвечено: у модельного ответа стоит «ответила модель мастера» с её именем, у отката — «ответил движок Point» и причина, по которой модель не ответила. Ядро различало это и раньше, но на экран не доходило, и молчаливый откат выглядел исправной работой.
- Подпись под чатом больше не описывает прежнее разделение «разговор — движок, модель только на запуске квеста»: теперь это «модель мастера — X · исполнение узлов — движок Point», а без модели так и сказано.
- Снят legacy-мост: профиль и чертёж больше не хранятся двумя таблицами в зеркале. Ядро держало их синхронными при старте, при каждом сохранении профиля и при каждом сохранении чертежа — отсюда шли почти все недавние дефекты: кнопка «Распустить» била в профиль, когда на экране был проектный агент; «знает ли ядро про Hub» определялось по наличию JSON-ключей; второй путь сохранения конструктора терял пять шагов из десяти. Теперь хранится чертёж, а профиль выводится из него на лету — как это давно делает ProjectAgent.
- Заодно исчезло расхождение, из-за которого было неизвестно, что уйдёт модели: у чертежа в `systemPrompt` лежал сырой текст, у профиля — скомпилированный, и результат зависел от того, какое сохранение было последним. Теперь хранятся и отдаются слои-источники, а собирает их запуск — одинаково при любом порядке сохранений.
- Ревью правки поймало в ней же две ошибки. Первая: если отдавать наружу собранный промпт, круг «прочитал профиль → сохранил» скармливает компилятору его же вывод — живая проба намотала четыре вложенных IDENTITY за три сохранения, и системное сообщение росло без предела. Вторая: `DeleteProfile` ходил в хранилище напрямую, мимо проверки занятости класса, — `/api/blueprints` отказывал, а `/api/profiles` с тем же id удалял и оставлял у персонажа ссылку в пустоту. Обе закрыты тестами.
- Миграции данных не потребовалось: `BlueprintFromProfile` сохраняет тот же идентификатор, поэтому сценарии, ссылающиеся на `profileId`, продолжают находить исполнителя. Живая проба подтвердила точную биекцию до правки. Отдельно добавлен разовый перенос для баз, сделанных версией до появления чертежей: раньше их переносил цикл зеркалирования, и вместе с мостом ушёл бы и он.
- Старый редактор карточки правит класс и говорит об этом своими словами: «Личность класса», «Экспорт класса», импорт класса. Персонажей правит конструктор Гильдии; двух ростеров и двух словарей больше нет.
- Чек-лист найма перестал звать нанимать за ядро: при отказе проверки он продолжал писать «Можно нанимать и сразу открыть квест», хотя баннер на том же экране уже честно говорил «Готовность неизвестна». Утверждение делалось по ответу, которого не было.
- Смоуки, поднимающие настоящее ядро, отказываются работать с устаревшим двоичным файлом. Правка ядра проходила Go-тесты, смоуки печатали PASS против вчерашней сборки, и расхождение вскрывалось только на следующей пересборке. Отсутствие файла они ловили и раньше; устаревание хуже — отсутствие видно сразу, а старый файл выглядит как успех.
- Класс, оставшийся от распущенного персонажа, можно убрать из списка найма. Конструктор, сохраняя персонажа «с нуля», заводит класс под него; живая проба трёх кругов «создал — распустил» оставила в списке найма три класса от несуществующих персонажей, и убрать их было нечем. Класс, которым кто-то пользуется, не удаляется: «класс занят персонажем «Занявший» — распустите его или смените класс».
- Онбординг больше не перепрыгивает собственный шаг «Создайте первого агента». Ростер брал `projectAgents`, а при отсутствии ключа откатывался на `profiles` — legacy-адаптеры чертежей. Ключ пропадал при пустом ростере, поэтому на свежей установке онбординг видел «в ростере 2» и, настроив компаньона и мастера, вёл сразу на «Готово»: человек заканчивал настройку, не создав ни одного персонажа. Замер до и после: шаг продолжения был «complete», стал «first-agent».
- Проектный агент проверяет режим подтверждений так же, как legacy-профиль. Неизвестное значение не равно «Каждое умение», поэтому движок молча считал его «спрашивать только про опасное» — из непонятного значения выходило послабление.
- Персонажа, созданного конструктором, теперь можно распустить. Раньше у ростера Гильдии не было такой кнопки вовсе, а у ядра — маршрута: ростер только рос. Единственная кнопка «Распустить» жила в старом редакторе профилей и на проектном агенте отвечала «Профиль агента не найден», потому что deleteProfile знает только legacy-профили.
- Роспуск отказывает там, где после него осталась бы ссылка в пустоту, и называет, что именно держит: «персонаж занят в запуске», «персонаж состоит в отряде «Биллинг» — сначала уберите его оттуда», «персонаж стоит в узле «Правка» схемы «Разбор вебхука» — замените его в схеме». Без последней проверки узел Flow не находил карточку уже на запуске, и наружу выходила сырая ошибка хранилища посреди работы, без всякой связи с давним роспуском. Хроника квестов при роспуске сохраняется, о чём и сказано в подтверждении.
- Пустой ростер больше не выглядит как старое ядро. Интерфейс решает, знает ли ядро про Hub, по наличию ключей `blueprints` и `projectAgents` в bootstrap, а оба стояли с `omitempty`: пустой список исчезал из ответа, и «агентов пока нет» становилось неотличимо от «ядро о них не знает». По второму прочтению конструктор уходит на legacy-путь сохранения, который теряет личность, миссию, ограничения, навыки и проектные правила — пять шагов настройки из десяти, молча. Ключи теперь присылаются всегда.
- И на случай, если legacy-путь всё же случится, конструктор называет потерю до сохранения, а не после: «в этом режиме не сохранятся: характер, миссия, ограничения, навыки, проектные правила».
- У компаньона была своя копия разбора текста — без списка служебных слов, который у мастера есть. Из-за этого ползунок «строгость уточнений» работал не так, как обещает: правило «в сообщении меньше трёх значимых слов — переспроси» считало значимыми «а что по этому», и при самой строгой настройке компаньон молча брался за пустую просьбу. Подбор отряда страдал тем же: совпадение по «за тем как» приносило агенту те же очки, что совпадение по существу.
- Правило совпадения слов теперь одно на мастера и компаньона — `internal/textutil`. Копий было две, и одно и то же обоснование, показанное человеку, зависело от того, кто его показывает.
- Отказ ядра больше не оставляет настройку ждать вечно. Годность персонажа и политика мастера спрашиваются отдельными запросами; ключ запроса клали в набор «уже спросили» и снимали только приходом ответа. При отказе ответа не бывает — ключ оставался там навсегда, а повтор блокировал сам себя, потому что смотрел в тот же набор. Карточка мастера застревала на «Политика считается ядром…» до переоткрытия панели.
- И то же самое, но опаснее: готовность персонажа при неполученном ответе намеренно не отрицается — «не наказывать за сетевой ход», — поэтому после отказа карточка навсегда заявляла «Персонаж готов к квесту» по данным, которых никто не присылал. Теперь она говорит «Готовность неизвестна: ядро не ответило». Гейт не тронут: запуск по-прежнему проверяет ядро.
- Автоповтора после отказа намеренно нет — постоянный отказ превратился бы в бесконечный поток запросов. Пометка снимается первым же удачным ответом ядра.
- Договорённость ядра и интерфейса №11: каждый набор `*Inflight` обязан упоминаться в обработчике отказа. Девятая договорённость сторожила только разделы с переменной `*Status`, а эти двое ждали ответа иначе и потому оставались незамеченными.
- Значения пресетов компаньона и мастера теперь сверяются между ядром и экраном настройки. Одни и те же числа записаны дважды — в `COMPANION_PRESETS`/`ORCHESTRATOR_PRESETS` и в `PresetDefaults` ядра, которым оно нормализует конфиг. Разъедутся — человек выберет «Наставника», увидит на ползунках одно, а помощник станет вести себя по другому набору; по отдельности этого не заметит ни один тест, потому что обе стороны внутри себя непротиворечивы. Сейчас сходятся все двенадцать пресетов, включая «Свои правила».
- Отметка навыка больше не снимает запрет, поставленный человеком. Шаг «Навыки» обещает «Skill сам не обходит DENY», и на исполнении это правда — но в настройке `applySkillToolGrants` молча переписывал политику значением из навыка: у встроенного Code Review в дельте стоит `read_file: ALLOW`, и осознанный DENY превращался в ALLOW без единого слова на экране. Обходить на исполнении было уже нечего. Теперь навык вправе дописать недостающую политику и ужесточить её, но не ослабить.
- Конструктор называет и вторую причину, по которой навык не заработает: умение в allowlist, но запрещённое политикой. Проверка нехватки смотрела только на allowlist и такой случай молчала — а именно он и получался после запрета.
- Сводка перед наймом не дорисовывает лимит ходов: при незаданном лимите в ячейке «ХОДЫ» стояло 30, притом что чек-лист на том же экране показывал «Лимит ✗», а ядро — «лимит ходов не задан». Теперь «—», как в соседней ячейке «МОДЕЛЬ».
- Агент держит те же границы, что ядро давно предъявляет компаньону и мастеру. Живая проба отправила девять заведомо неверных настроек в `POST /api/project-agents` — все девять были приняты: температура 99 и −5, ответ в 900000 токенов, −10 ходов, провайдер «skynet», схема `ftp://`, адрес без схемы и, главное, ключ прямо в адресе провайдера (`http://admin:s3cret@example.com/v1`), который компаньону ядро запрещает отдельным правилом. Границы взяты не с потолка: это те самые `min`/`max`, которые конструктор агента объявляет полями формы. Ноль в лимитах остался разрешённым — это «не задано», и ядро говорит о нём отдельно.
- Правило адреса модели стало одним на троих: компаньон, мастер и агент проверяют схему и запрет учётных данных в URL одним кодом. Раньше правило было записано дважды, а для агента — ни разу.
- Агент с моделью, но без провайдера больше не числится готовым к квесту: проверка спрашивала только имя модели, а обратиться к ней было не через что. Отказ приходил на старте квеста словами `unsupported provider kind ""` — там человек и узнавал, что настройка не закончена. Теперь причина называется на карточке персонажа вместе с шагом, где чинится.
- Ядро больше не заводит персонажа, которого нельзя назвать: живая проба показала, что `POST /api/project-agents` принимал имя «», «   » и «Раз
ведчик» — в ростере появлялись карточки, неотличимые друг от друга и безымянные в отряде и в снимке квеста. Имя теперь сводится к одной строке, а пустое отклоняется с «укажите имя агента». Интерфейс это и так не пропускал, но он не единственный клиент.
- Карточка выбора на шаге «Мозг мастера» была подписана «Модель компаньона» — тем самым, чем она по собственному тексту не является («Это не диалог компаньона», «Своя модель, не компаньон»). Теперь «Своя модель мастера».
- Со шага «Мозг мастера» убрано предложение, напечатанное дважды подряд: «Исполнение узлов всё равно идёт через движок Point. Исполнение узлов всё равно идёт через движок Point.»
- Enter в конструкторе агента гасит прежнюю ошибку так же, как кнопка «Сохранить»: имя исправляли, сохранение уходило, а под шагами продолжало висеть «Укажите имя агента».
- Экран настройки Мастера больше не пишет ползунок двумя алфавитами: «Строгость revью» — «rev» латиницей, «ью» кириллицей. В превью Мастера подпись заглавными, и промах читался как «СТРОГОСТЬ REVЬЮ». Такое слово не находится поиском ни по одному написанию; сборка теперь падает на любом слове из двух алфавитов.
- Шаг «Мозг компаньона» перестал приписывать компаньону работу Мастера: там было сказано, что компаньон «назначает отряд и запускает Flow» — на том самом шаге, который представляет Мастера как отдельного диспетчера. Компаньон только предлагает; отряд назначает и Flow запускает Мастер после Start.
- Счётчики в найме и настройке агентов согласуются с числом: «даёт 2 умений» на шаге первого агента, «1 общ. умений» в синергии ростера, «N умений · M ходов» на карточках классов, «1 сбоев», «1 отказов», «1 предложений ждут Start», «1 активных запусков», «0 / 1 узлов». Пятнадцать мест, где форму слова выбирал автор строки, а число приходило из данных.
- Проверка склонения перестала пропускать определение между числом и словом: «${item.shared} общ. умений» она не видела, потому что искала существительное вплотную к подстановке. Заодно в список считаемых слов добавлены умение, ход, отказ, сбой, узел, предложение, навык, инструмент, шаблон, задача и проверка — на них и нашлись все пятнадцать.
- Снимок снаряжения квеста не выдаёт незаданный лимит за нулевой: при `maxSteps < 1` ядро говорит «лимит ходов не задан», а карточка написала бы «0 ходов». Теперь там «ходы без лимита» и «время без лимита».
- Пустой ростер больше не делает Мастера односложным: «что ты умеешь», «что сейчас», «кто есть» и «привет» получают свои ответы, а не одно и то же предложение нанять. Найм предлагается на задачу — и роль подбирается под названную задачу, а не под текст приветствия.
- Повтор той же задачи не плодит второе предложение: Мастер показывает уже ждущее решения, вместо того чтобы класть в очередь ещё одно с тем же названием и сообщать о «предыдущем» с этим же заголовком.
- Подробности задачи доходят до квеста: всё, что человек написал после первой строки, становится целями квеста — раньше оно не попадало никуда, а в целях стоял перечень отряда, уже показанный карточкой рядом.
- Задача, написанная по-английски, больше не теряется: «fix flaky billing test» уходило в общий ответ «опишите задачу», хотя задача была описана. Глаголы сверяются по целым словам, поэтому «prefix» и «address» задачей по-прежнему не считаются.
- Отказ «никто не доведёт работу до конца» ведёт кнопкой в гильдию, где агента и чинят: прежде там стояла подсказка «открыть карточку агента», которая уходила Мастеру репликой и возвращала тот же отказ.
- Мастер сдерживает обещание вернуться к задаче: «наймите его, и я сразу предложу квест» и «поправьте их настройку, и я предложу квест» теперь работают — сказав «нанял» или «поправил», человек получает предложение по той самой задаче, а не просьбу описать её заново.
- Подсказки под ответом Мастера перестали водить по кругу: чип уходит ему же следующей репликой, а его собственный вопрос он отвечал той же строкой, под которой чип и стоял. Теперь это «что сейчас?» и «кто есть в ростере?» — на них он действительно отвечает; обещание «что поменять в предложении?» убрано, потому что править предложение из разговора нечем.
- Разговор с Мастером закреплён проверкой на потерю работы: набранное переживает чужую отрисовку, Enter отправляет, отказ ядра отпирает поле и оставляет реплику на месте, а незагрузившаяся переписка даёт кнопку повтора вместо переоткрытия панели.
- Числа в ответе Мастера сходятся между собой: сводка и кнопка перехода берут один снимок мира на ход, а не каждая свой — иначе один ответ мог сказать «ждут решения: 3» и подписать кнопку «разобрать очередь (2)». Вопрос к Мастеру заодно подешевел: снимок — это вся очередь решений целиком.
- Состояние мира перестало расти от разговоров с Мастером: решённые предложения квестов уезжали клиенту все и навсегда — замер показал 38 КиБ на шестидесяти ходах в каждом запросе. Теперь их не больше пятидесяти свежих, а открытые по-прежнему доезжают все, сколько бы их ни было.
- Путь от разговора с Мастером до запущенного квеста проверяется целиком на живом ядре: задача → предложение → очередь решений → запуск → квест и прогон Flow, включая отказ от повторного запуска. Именно отсутствие такой сквозной проверки и позволило очереди решений сломаться незаметно.
- Очередь решений снова решает: подтверждение шага, узел Flow, предложение квеста и действие компаньона принимались и отклонялись запросом той формы, которую ядро отвергало целиком — каждое нажатие возвращало 400. Теперь маршрут сам описывает, как назвать поля запроса, а кнопка и горячая клавиша собирают его одним кодом.
- Основания ответа Мастера не спорят сами с собой: «отряд по политике: до 3» вместо «размер отряда: 3» рядом с ростером из двух агентов.
- Карточка найма держит длинное имя чертежа: имя переносится внутри карточки, а подпись кнопки ограничена — прежде кнопка «НАНЯТЬ «…»» выезжала за карточку и уводила ленту разговора в горизонтальную прокрутку. Полное имя осталось в подсказке.
- Длинное имя агента в составе отряда обрезается, а не печатается поверх причины неготовности: обе строки становились нечитаемыми, а лента разговора уезжала вбок. Полное имя и полная роль остались в подсказке.
- Текст в тройных кавычках в одну строку больше не пропадает: раньше `\`\`\`go build\`\`\`` разбиралось как блок кода без содержимого — на экране оставалась пустая рамка с кнопкой «копировать код», а написанное исчезало молча. Теперь это врезка, как и задумано разметкой.
- Настроив Мастера, человек возвращается в разговор, а не к тому же приглашению настроить: раздел узнаёт о появившемся диспетчере из состояния мира и перезапрашивает переписку. Прежде выход был один — переоткрыть панель.
- Состав отряда виден и там, где квест не предложен: на «кто есть в ростере» и на отказ «никто из подходящих не доведёт работу до конца». Раньше состав рисовала только карточка квеста, и совет «поправьте их настройку» не называл ни агентов, ни чего им не хватает, хотя ядро это считало и присылало.
- Одно предложение — один квест: повторный запуск отвергается ядром, а кнопка на время ожидания запирается и говорит «запускаем…». Раньше второе нажатие создавало второй квест со своим отрядом, Flow и прогоном — те же агенты выходили на ту же задачу и тратили бюджет дважды.
- Отклонённое предложение перестаёт быть предложением: кнопка «Запустить» на нём больше не остаётся и не запускает то, от чего только что отказались. Само отклонение больше не выбрасывает из разговора с Мастером в обзор — уводит с места только запуск квеста.
- Реплика в чате остаётся текстом при любом соседстве: абзац с блоком кода возвращался без экранирования, и чужой тег рядом с блоком попадал в разметку как разметка — а через реплику Мастера туда доходит написанное человеком. Прикрыто смоуком, который держит и обратную сторону: блоки, списки, врезки и ссылки на файлы продолжают работать.
- Присланное ядром в ответе на ход показывается всегда: карточка квеста, основания и уточняющие вопросы больше не зависят от того, проставлена ли метка на сохранённой реплике.
- Длинный разговор с Мастером признаётся хвостом: лента говорит, что показаны последние реплики и начало осталось раньше, вместо того чтобы молча начинаться с середины. Ровно предел реплик хвостом не считается — пометка врала бы про пропавшее начало.
- Тревога очереди в шапке стала кнопкой и научилась склонению: «1 ЖДЁТ РЕШЕНИЯ» вместо «1 ЖДУТ», а клик ведёт в саму очередь — из разговора с Мастером туда можно было попасть только через возврат в Чертог. Проверка склонений теперь видит и глаголы после числа, а не только существительные.
- Мастер помнит, что сам же и предложил: «давай» или «ок» после предложенного квеста больше не получают в ответ приглашение описать задачу, а вторая задача не добавляет предложение в очередь молча — о ждущем первом сказано в ответе. Отклонённое предложение назад не зовёт.
- Вопрос Мастеру стал дешевле: два запроса к ядру после хода (включая полный bootstrap) уходят только когда ход создал предложение квеста, и уходят вместе, а не друг за другом. Длинное название квеста режется по слову и с многоточием — обрубок посреди слова читался в очереди решений как законченное имя.
- Уточняющие вопросы Мастера перестали быть светлыми системными кнопками на тёмной панели: фон чипа назван явно, контраст мелкого текста вырос втрое, а длинный вопрос переносится по словам вместо того, чтобы выталкивать всю ленту в горизонтальную прокрутку.
- В разговоре с Мастером всё приложенное к реплике — основания, решённое предложение, уточняющие вопросы и кнопки перехода — встало под её текстом: отступ считается из сетки реплики, а не вписан числом, которое разошлось с ней на четыре пикселя; кнопки перехода раньше не были выровнены вовсе.
- Мастер больше не жалуется на исправную модель: в разговоре он её не зовёт, поэтому отряд подписан как предварительный, с оговоркой, что при запуске состав пересоберёт модель. Подпись под полем ввода называет, кто отвечает — движок Point, — а пресет без модели перестал выглядеть недонастроенным.
- Состав отряда объясняется по существу: предлоги и союзы больше не попадают в «совпало» и не поднимают агента в подборе, повтор слова в задаче считается за одно совпадение, а перечисление ростера не показывает оценку соответствия задаче, которой не было.
- Мастер слышит задачу, даже если в ней есть слова «статус», «состояние» или «команды»: раньше упоминание перебивало глагол, и на «Добавь команды в CLI» приходила справка. Сводку он больше не выдумывает — не сумев свести очередь и наборы изменений, так и говорит, вместо уверенного «ничего не ждёт вашего решения».
- Предложенный квест остаётся в разговоре с Мастером: карточка, основания и ссылка на предложение переживают перезапуск панели, решённое помечается прямо в переписке, а повторяющиеся основания больше не дублируются на каждом ходе.
- Разговор с Мастером больше не теряет набранное и не замирает: поле переживает перерисовку, отказ ядра снимает замок и возвращает реплику, лента держится на последнем ответе, Enter отправляет, а непришедшую переписку можно перезапросить кнопкой.
- Ежедневный кодинг ближе к JetBrains: статус-бар показывает текущий символ (клик — Ctrl+F12), Ctrl+E возвращает к файлу с позицией курсора, Alt+Home — навигационная строка, Ctrl+Shift+B — тип, Ctrl+Shift+↑/↓ — сдвиг строк.
- Структура без LS читает и Java/Kotlin/C#; при сохранении organize+format больше не глотают друг друга. Sticky scroll и крошки идут по позиции в файле.
- Хаб держит один ритм: плотные вкладки, шапка не разъезжается, чат заполняет высоту без `vh`-скачков, карточки Start/Modify/Ignore живут вне ленты.
- На узком экране Журнал/Наборы уходят в карту «Сейчас»; на низкой высоте карта скрывается. Онбординг и страницы гильдии делят общие отступы и заголовки.
- Ревью ядра: индекс больше не гоняет карты без копии, сбой модели помечает запуск Failed, usage не принимает чужой мир и чужую стоимость, кастомные инструменты наследуют DENY сети, Apply резолвит симлинки.
- После Stop автоиндекс не поднимает ядро. Онбординг пишется в `workspaceState` текущего мира. Быстрый чат и inbox открывают только Хаб и только файлы внутри папки.
- Хром IDE ближе к JetBrains New UI: поиск в шапке без кнопок назад/вперёд, плотные вкладки и деревья 22px, sash 2px, единый выбор в списках и Search Everywhere.
- Шапка компактнее: chip проекта 24px, command center уже, одна линия под titlebar. Крошки без иконок; dirty-tab — квадрат, не точка.
- В шапке — Поиск везде, Запуск и компаньон. Крошки показывают весь путь, как Navigation Bar; повторный клик по иконке слева закрывает окно.
- Онбординг ведёт по четырём актам: компаньон → оркестратор → первый агент → гильдия. Стартовый экран показывает карту и «Начать» / «Продолжить» с незакрытого шага.
- Пока не настроены оба системных агента, «Обзор» из онбординга закрыт. «Далее» на первом агенте принимает предложение компаньона, финал сразу открывает гильдию или квест.
- Автоиндекс больше не сбрасывается из‑за одного сохранения: поиск и компаньон догоняют файл точечно, папка удаляется целиком, одинаковое содержимое не перечитывается.
- Сохранение индексируется за доли секунды; пачка файлов по-прежнему ждёт паузу. Если точечное обновление падает — один полный проход, без потери списка изменений.
- Редактор живёт без language server: Ctrl+F12 читает структуру текущего буфера, поиск везде помнит закрытые файлы, статус-бар показывает число ошибок.
- Ctrl+Alt+Shift+C копирует ссылку `файл:строка`, черновик кладётся в `.point/scratches`, файлы сравниваются из Инвентаря. Ctrl+Alt+S переключает формат при сохранении, липкую структуру и крошки.
- Диалог компаньона читается как чат: выше лента, пузыри сообщений, чипы фокуса IDE, Enter отправляет, рельс показывает последний ответ карточкой.
- Общение с компаньоном держит нить: локальный разбор помнит прошлый ответ, ошибка остаётся в ленте, чип фокуса сразу спрашивает, а не только подставляет черновик.
- Обзор снова штаб гильдии: квест и ревью сверху, компаньон занимает сцену только когда идёт диалог или есть карточки Start / Modify / Ignore.
- Журнал, наборы и статистика доступны с полоски «Сейчас» и из шапки. В наборах видны файлы и diff перед Apply.
- Визуал Хаба собран в Point Dark: сетка, угловые насечки, консоль ввода, живое свечение компаньона без круглых пилюль.
- `Ctrl+Alt+;`, CodeLens, inbox и статус-бар открывают диалог компаньона в Хабе, а не пустой сайдбар. Ответ больше не теряется на рельсе и не обрывается через 20 с.
- Shift+F10 запускает текущую цель Point (launch, tasks, npm, go, make, cargo), а не пустой debug.run. Статус-бар помнит выбор; Alt+Shift+F10 выбирает; файл можно запустить из Инвентаря.
- Компаньон видит текущий файл:line, hover/Quick Fix готовят исправление, статус открывает inbox сигналов, терминал и SCM отдают Analyze failure / diff. Квест по-прежнему не стартует сам.
- Компаньон читает цель Shift+F10, кадр отладки, blame/историю и несохранённый буфер. На ошибках редактора — CodeLens «подготовить исправление»; сбой `Point ·` терминала предлагает разбор.
- Внешний LLM подключается как обычный шлюз: LLMux / свой endpoint, URL и токен. Токен живёт в SecretStorage и больше не пропадает при кликах в мастере.
- Мастер компаньона не перерисовывает весь Хаб на каждую кнопку: экран не скачет, токен не сбрасывается, карточки источника не прыгают.
- Помощник держит внимание на курсоре: выделение важнее окрестности, диагностика открытого файла идёт первой, а после ответа появляются живые уточнения «исправь / разбери запуск».
- Компаньон доступен из статус-бара, палитры и хоткея `Ctrl+Alt+;`; выделение и диагностика открываются через «Обсудить с компаньоном».
- На ошибках редактора есть Quick Fix «Спросить компаньона»; сбой VS Code Task предлагает тот же разбор.
- Квесты, Флоу, Отряды и Ростер показывают компактную полоску компаньона: сигнал, открытие файла и быстрый вопрос.
- IDE-диагностика несёт путь и строку; рекомендация открывает файл в редакторе.
- Studio и онбординг описывают компаньона как помощника всей IDE, а не только OAuth/квестов.
- Настройка компаньона больше не показывает отряд/квест и не пускает в конструктор агента, пока не выбран мозг помощника.
- Первый агент в онбординге предлагается Companion карточкой: принять, изменить в конструкторе или сменить шаблон.
- Конструктор показывает матрицу Risk × Policy (ALLOW / ASK / DENY); DENY больше не обходится карточкой подтверждения.
- Change Journal собирает Quest → Execution → Action с откатами; вход с Обзора и наборов изменений.
- Онбординг модели, навыков и разрешений настраивается на месте, без ухода на другие вкладки; ключ больше не пишется в webview state.
- Bootstrap, Runs, Journal и Statistics больше не показывают чужие миры: runs, patches и пути папок остаются в текущем проекте; Blueprints, Skills и Connections по-прежнему общие.
- Apply / Reject / Revert Change Set и детали запуска отвергают чужой `workspaceId`; git-репозиторий получает detached worktree, иначе остаётся filtered copy.
- Конструктор больше не собирает промпт на JS: шаг «Обзор» показывает тот же system message, что уйдёт в рантайм (identity + skills + execution contract).
- Статистика открывается отдельным окном IDE (`localAgent.openStatistics`, Обзор → «Подробная статистика»), без девятой вкладки в оболочке Гильдии.
- Компаньон и оркестратор — два разных системных агента со своими моделями. Оба настраиваются в начале онбординга: компаньон сопровождает IDE и только рекомендует, оркестратор назначает отряд и стартует Flow.
- Обзор Хаба читается как командный центр: живая полоска «сейчас», понятные вкладки с подписями, цветовые акценты карточек и следующий шаг вместо одинаковых коробок.
- Хром IDE: пустой редактор показывает действия Point, главная — компаньона и гильдию, статус-бар и activity bar различают мир / компаньона / гильдию.
- Поиск везде, переход к определению и Find Usages опираются на локальный индекс Point, если language server молчит. Компаньон разбирает Problems и символ под курсором.
- Индекс обновляется точечно при правках файлов, поиск идёт по инвертированному словарю, а живой компаньон больше не тянет весь bootstrap.

## 1.2.1 — Agent Hub runtime foundation

- `ProjectAgent` стал канонической запускаемой сущностью; Blueprint и legacy profile используются как шаблон и совместимый адаптер.
- Прямые запуски создают Quest и сохраняют сквозную связь с Execution, Usage и ProjectAgent; добавлены лимиты Quest.
- Backend компилирует слоёный prompt, память сохраняет provenance, а Skill не может расширить разрешения агента.
- Flow валидируется как достижимый граф без обычных циклов; Tool nodes исполняются детерминированно, а Loop ограничен `maxIterations` 1–20 и явными ветками `continue` / `done`.
- Companion может использовать настроенную Ollama/OpenAI-совместимую модель с ключом только из SecretStorage; ответ проходит строгую JSON-проверку, а ошибка безопасно переключает диалог на deterministic fallback.
- Companion различает вопросы, анализ проекта и запросы на работу: статус и статистика больше не создают QuestProposal. Анализ Usage Records сравнивает текущий и прошлый месяц, показывает главные модели/агентов и явно отмечает неизвестную стоимость; уточняющие вопросы сохраняются в истории.
- Проактивные рекомендации Companion можно скрыть и вернуть. Скрытие изолировано по проекту и относится только к наблюдаемому состоянию: изменившаяся или повторно возникшая проблема снова становится видимой.
- По явному запросу Companion подготавливает типизированный черновик Flow с узлами, связями и выбранными агентами. Черновик можно проверить, изменить или игнорировать; Flow появляется в проекте только после кнопки «Создать Flow», повторное и межпроектное применение запрещено.
- Companion получает текущие Problems и результаты терминала/VS Code Tasks, объясняет конкретные ошибки и подготавливает проверяемый квест исправления с файлами, строками и требованием успешной команды.
- Явные запросы создать Agent или Team теперь дают типизированный черновик с выбранным Blueprint/составом. Изменение и игнорирование ничего не создают; сущность появляется только после подтверждения пользователя.
- Companion создаёт проверяемый Skill-черновик с инструкциями и явным списком tools. Черновик не может скрытно добавить scripts, references или permissions; после подтверждения создаётся global definition и Project Skill Instance текущего проекта.
- Inline Companion в конструкторе агента остаётся неблокирующим: рекомендации tools применяются только кнопкой «Добавить» и могут быть отдельно проигнорированы.
- Во время активного execution Companion теперь отслеживает pending approvals, повторные ошибки tools, усечённый поиск, давление контекста, запросы повторной проверки и provider retries по локальной хронике Run.
- Рекомендация может открыть точный execution или предложить готовое корректирующее сообщение агенту. Сообщение отправляется только после явного нажатия пользователя; approvals и политики Companion самостоятельно не меняет.
- Активные рекомендации обновляются в фоне, но интерфейс перерисовывается только при изменении evidence/occurrence, поэтому Companion не мешает работе редактора.
- Bootstrap сообщает реальные гарантии sandbox backend; Command Center явно показывает отсутствие process/network/OS-изоляции у filtered-copy режима.
- Change Set хранит точные снимки, применяет все файлы атомарно и поддерживает конфликт-безопасный Revert.
- Sandbox copy/diff использует единый фильтр, исключает секретные файлы и очищает среду дочерних процессов от credential-переменных.
- Статистика позволяет задать отдельные для каждого проекта дневной и месячный бюджет; на 80% показывается предупреждение, а опциональный hard stop блокирует новые запуски по фактически известной стоимости.

## Точечные правки без повторной отправки файла

- Для небольшого изменения агент теперь использует точные уникальные замены `oldText → newText`; полный текст остаётся для новых файлов и цельных переписываний.
- Неоднозначные, отсутствующие, пересекающиеся и пустые якоря отклоняются до подтверждения и возвращаются агенту как исправимая структурированная ошибка.
- Point собирает итоговый файл локально и показывает компактные diff-блоки с контекстом. Замена одной строки в большом повторяющемся файле больше не разворачивает весь файл в ревью.
- Старые полнофайловые вызовы `propose_patch`, подтверждение, проверка SHA-256, история и безопасный откат сохранены.

## Защита чтения перед изменением

- Point теперь технически блокирует слепую правку: существующий файл должен быть полностью прочитан в предыдущем ходе агента, а его SHA-256 — совпадать с текущим файлом на диске.
- Чтение и патч в одном ответе модели не считаются безопасной последовательностью; агент получает структурированную подсказку и может исправиться в следующем ходе.
- Внешнее изменение файла делает наблюдение устаревшим, освобождает повторное чтение и не позволяет потерять пользовательскую правку.
- Новые файлы требуют предварительного списка проекта или чтения соседнего файла. Защита видна в хронике квеста и локальной диагностике.

## Completion evidence cycle

- Финальный текст агента больше не означает автоматический успех: Point локально сверяет его с реальными результатами инструментов и актуальной ревизией файлов.
- Если после изменения файлов не было успешной проверки, агент получает одну ограниченную попытку исправиться и вызвать разрешённый `run_command`; повторное голословное завершение отклоняет квест.
- Явное требование запустить тесты, сборку или линтер нельзя обойти текстом, а отсутствие разрешённого инструмента становится понятной проверяемой причиной остановки.
- Команда считается успешной только при `exitCode: 0` без тайм-аута. Неуспешную команду можно повторить, и она больше не попадает в защиту от повторного успешного действия.
- `echo`, команды версии и shell-выражения, способные скрыть ошибку тестов, не считаются доказательством; принимаются только распознанные тесты, сборка, линтер или статический анализ.
- События `completion.checked`, метрики и сигналы диагностики показывают запрос доработки, принятие после исправления или окончательное отклонение.
- «Разведка» до запуска показывает условия завершения и заранее подсвечивает квест, где обязательная проверка несовместима с разрешениями выбранного агента.
- При блокирующем контракте кнопка старта отключается, а backend повторно проверяет условие и не создаёт запуск, событие или запрос к модели.
- Пользовательский command/process tool можно явно отметить как «Доказательство готовности»; разрешённый инструмент с `exitCode: 0` без тайм-аута участвует в runtime gate и диагностике.
- Флаг verifier-а сохраняется в SQLite, JSON import/export и неизменяемом снимке запуска; старые инструменты остаются обычными и не получают доверие автоматически.

## Rolling context cycle

- Для каждого агента настраивается контекстное окно модели; Point заранее резервирует лимит ответа и показывает доступный входной бюджет.
- Длинный квест больше не отправляет модели всю накопленную переписку: старые полные раунды инструментов заменяются детерминированной локальной памятью, а последние раунды сохраняются целиком.
- Пары assistant/tool никогда не разрываются. Слишком большой результат инструмента сокращается в валидный JSON с размером, SHA-256 и UTF-8-безопасным фрагментом.
- Полная хроника событий и результаты инструментов не удаляются. Каждое уплотнение записывается как `context.compacted`, отображается в квесте и входит в локальную диагностику.
- После удаления старого read-only результата агент может безопасно прочитать его снова; выполненные патчи, команды и пользовательские инструменты повторно не разрешаются.

## Agent reliability cycle

- Временные ошибки провайдеров теперь повторяются не более трёх раз с экспоненциальной задержкой и поддержкой `Retry-After`; каждый повтор виден в неизменяемой хронике и диагностике.
- Успешный семантически одинаковый вызов инструмента не исполняется повторно на той же ревизии проекта, а три одинаковых плана подряд безопасно останавливают зациклившегося агента.
- Невалидные JSON-аргументы tool call возвращаются модели как структурированный `invalid_input`, чтобы она могла исправиться без потери всего запуска.
- Пустой ответ модели больше не считается успешным квестом.
- System prompt получил capability-aware execution contract и больше не требует поле `reason` у read-only инструментов, в схемах которых такого поля нет.

## RPG interface

- Point получил собственную RPG-дизайн-систему: Инвентарь, Летопись, Гильдия, квесты, Хроника, умения и артефакты.
- Карточки персонажей показывают класс, уровень, надёжность и умения, рассчитанные только по фактическим данным профиля и запусков.
- Нативная оболочка, главная, редактор, панели и меню используют единую тёмную палитру, 1 px границы и компактную геометрию.
